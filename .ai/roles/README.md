## Запуск Keeper

### Вариант 1: Последовательно (один Keeper)

```
Роль: keeper
```

Keeper сам управляет backlog: запускает `backlog_update.py`, выбирает батчи, обрабатывает, фиксирует.

### Вариант 2: Параллельно (несколько окон)

1. **Principal обновляет backlog и нарезает батчи:**
```
Роль: principal

Запусти: python scripts/backlog_update.py
Посмотри keeper_state.json → backlog.
Разбей на батчи (≤3 секций или ≤5 файлов).
Для каждого батча дай готовый промпт по шаблону из .ai/roles/README.md → "Шаблон промпта для Keeper".
```

2. **Шаблон промпта для Keeper:**
```
Ты выполняешь роль Keeper.

## Инструкции
Прочитай: .ai/roles/keeper.md
Следуй алгоритму начиная с Шага 4 (Выполнение).

## Контекст
Шаги 1-3 уже выполнены. Твой батч:
- [файл 1]
- [файл 2]
- ...

## Ограничения
- НЕ запускай backlog_update.py в начале (уже запущен)
- `--done` ТОЛЬКО после моего явного одобрения! (иначе mtime-баг: файлы с временем изменения > updated_at снова попадут в backlog)
- НЕ выполняй Шаг 7 (следующий батч) — только твой батч
```
