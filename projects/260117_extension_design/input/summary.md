### 1. Концепция: Разделение ответственности

* **Google Drive** — это **Реестр (Registry)** и **Конфигурация**. Здесь хранится структура «Древа Жизни» (бизнесы, отделы), документация, мета-данные проектов и секретные файлы (`.env`).
* **Локальный Диск** — это **Среда исполнения (Runtime)** для тех продуктов которые хранятся в Git. Здесь хранится всё что в Git, история Git и зависимости (`node_modules`) для максимальной производительности.

#### Тезаурус

| Термин | EN | Значение | Пример |
|--------|----|----------|--------|
| **Бизнес** | business | Корневая сущность, верхний уровень | `МетаЛаб`, `СоциоЛаб`, `Трейдинг`, `Семья`, `База` |
| **Дело** | stream | Отдел/поток работы внутри бизнеса | `ТехноЛаб`, `ДомоДел`, `ДетРазвит`, `СоциоТеор` |
| **Продукт** | product | Конкретный deliverable с репозиторием/папкой | `Duet`, `Kreator` |
| **Компонент** | component | Часть продукта (пакет в монорепе) | `packages/ai-kit`, `packages/extension` |
| **Проект** | project | GTD-проект: группа задач с критерием конца | проектная папка `drafts/260110_ai_talks` |

> **Иерархия:** Бизнес → Дело → Продукт → (Компонент) → Проект
>
> Бизнес и Дело — долгоживущие. Продукт — может жить долго. Компонент — опционален. Проект — завершается.

### 2. Структура данных

#### На Google Drive

**Манифесты** — JSON-файлы, определяющие сущности:

```jsonc
// business.json
{
  "name": "МетаЛаб",
  "icon": "🔬"
}

// stream.json
{
  "name": "ТехноЛаб",
  "icon": "💻"
}

// product.json
{
  "name": "Duet",
  "icon": "🎭",
  "local_folder": "Duet",        // имя папки в ~/DuetData/repos/
  "git_url": "git@github.com:user/duet.git",  // опционально
  "hydrate": [".env", "secrets/"]  // файлы/папки для симлинков
}
```

**Правила:**
- `name`, `icon` — обязательные для всех
- `git_url` — опционально (продукт может жить только на Drive)
- `hydrate` — список путей относительно папки продукта на Drive
- `local_folder` — имя папки в repos/ (по умолчанию = name)

**Гидратация = симлинки:** После клонирования создаются симлинки из git-repo → Drive для файлов из `hydrate[]`. Источник истины — Drive.

#### На Локальном Диске (ПК/Mac)

Существует одна корневая папка (например, `C:\Users\...\DuetData\repos` или `~/DuetData/repos`), заданная в __глобальных__ настройках VS Code. Внутри неё клонируются папки из git-репозиториев.

#### SQLite индекс (кэш иерархии)

Сканирование Google Drive может быть медленным. Поэтому храним индекс локально:

```
~/DuetData/
├── data/
│   └── index.db      ← SQLite: иерархия, пути, метаданные
└── repos/
    └── ...
```

- **Первый запуск:** полное сканирование Drive → создание индекса
- **Дальше:** читаем из `index.db` (мгновенно)
- **Обновление:** по кнопке 🔄 в sidebar или при первом запуске после N дней

### 3. Логика работы расширения (Launcher)

#### А. Сканирование и Отображение

1. Расширение сканирует Google Drive (Multi-root workspace).
2. Находит все файлы `business.json`, `stream.json`, `product.json`.
3. Также распознаёт **проектные папки** внутри продуктов (папка `projects/` с подпапками).
4. Строит в боковой панели иерархическое дерево дел на основе папок Драйва.

#### Б. Действие по клику (Запуск)

При клике на проект расширение вычисляет целевой путь: **Локальный Корень (из настроек) + Имя папки (из json)**.

**Сценарий 1: Проект уже есть локально**

1. Расширение просто открывает эту папку в **новом окне** VS Code.

**Сценарий 2: Проекта нет (первый запуск на устройстве)**

1. **Клонирование:** Расширение выполняет `git clone` по URL из манифеста в целевую папку.
2. **Гидратация (Связывание):** Расширение создает в локальной папке проекта символическую ссылку (или копию) файлов из Google Drive (`.env` и т.п.). Список папок для гидратации указывается в `product.json`.
3. **Старт:** Открывает папку в новом окне.

#### В. Два режима работы

**Обзорный режим:** Открываю родительское дело (например, `СЕМЬЯ`) и обозреваю всю структуру вложенных дел и продуктов. Не работаю прицельно — просто навигация.

**Прицельный режим:** Открываю конкретный продукт в отдельном окне. Подтягиваются `.ai/` инструкции, фокус на работе с кодом.

#### Г. UI боковой панели

**Технология:** Один VS Code TreeView с несколькими секциями.

**Структура панели:**

```
┌─────────────────────────────────────┐
│ 🔄 ⚙️                              │  ← Header с кнопками
├─────────────────────────────────────┤
│ ▼ 🔬 МетаЛаб                       │  ← Breadcrumb (tree, always expanded)
│   ▼ 💻 ТехноЛаб                    │
│     ● Duet [hydrated ✓]            │
│                                     │
│ ▼ ⚠️ ОШИБКА: не связан с продуктом │  ← Если есть ошибка (кликабельно)
├─────────────────────────────────────┤
│ ▼ Дерево дел                       │  ← Main tree
│   ▼ 🔬 МетаЛаб                     │
│     ▼ 💻 ТехноЛаб                  │
│       ● Duet ← выделен             │
│       ○ Kreator                    │
│   ▶ 👨‍👩‍👧 Семья                       │
└─────────────────────────────────────┘
```

**Элементы:**
1. **Кнопка 🔄** — обновить дерево (пересканировать Drive)
2. **Кнопка ⚙️** — открыть настройки расширения
3. **Breadcrumb** — tree-секция, всегда раскрыта, один элемент на уровень
4. **Ошибка** — кликабельный элемент → открывает editor с инструкцией
5. **Дерево дел** — полное дерево, текущий элемент выделен (bold + accent)
6. **Кнопки у элементов:** открыть в текущем/новом окне

**Emoji:** берутся из поля `icon` в манифестах (business.json, stream.json, product.json).

#### Д. Orphan Repo (несвязанный репозиторий)

Если папка в `~/DuetData/repos/` не найдена в `index.db`:

**UI в sidebar:**
```
▼ ⚠️ ОШИБКА: не связан с продуктом
```

**Клик** → открывается Editor Tab с инструкцией:
- Объяснение проблемы
- Кнопка "Связать с существующим продуктом" → QuickPick
- Кнопка "Создать новый продукт"
- Кнопка "Игнорировать"

**QuickPick:**
```
> Выберите продукт для связывания:
  🔬 МетаЛаб / 💻 ТехноЛаб / Duet
  🔬 МетаЛаб / 💻 ТехноЛаб / Kreator
  + Создать новый продукт...
```

#### Е. Архитектура: логика в каждом окне

Расширение работает в каждом окне VS Code. Дерево показывается везде одинаково.

**Любое окно:**
- Показывает полное дерево из `index.db`
- Выделяет текущий контекст в breadcrumb и TreeView
- Может обновить дерево, открыть настройки

**Окно git-repo (дополнительно):**
- Определяет: это git-repo? (наличие `.git/`)
- Находит свой `product.json` на Drive (по имени папки в `index.db`)
- **Авто-гидратация** при активации окна
- **File watchers** на Drive-источники после гидратации

> Гидратация и watchers — ответственность окна git-repo.

#### З. File Watchers

После успешной гидратации запускаем watchers:

| Что отслеживаем | Где | Реакция |
|-----------------|-----|---------|
| `product.json` | Drive | Перечитать манифест, проверить hydrate[] |
| Файлы из `hydrate[]` | Drive | Обновить копии в git-repo |

**Упрощение:** Парсить JSON при старте — не проблема. Полный re-scan дерева — только по кнопке 🔄 от пользователя. Для одного файла проще читать напрямую, чем лезть в БД.

#### И. Схема index.db

```sql
-- Сущности с Drive
CREATE TABLE entities (
  id INTEGER PRIMARY KEY,
  type TEXT,              -- business | stream | product | project
  name TEXT,
  icon TEXT,              -- emoji из манифеста (🔬, 💻, 👨‍👩‍👧)
  drive_path TEXT UNIQUE,
  parent_id INTEGER REFERENCES entities(id)
);

-- Маппинг склонированных продуктов
CREATE TABLE local_repos (
  product_id INTEGER PRIMARY KEY REFERENCES entities(id),
  local_path TEXT,
  cloned_at INTEGER,
  last_hydration INTEGER
);
```

#### К. Edge Cases

| Ситуация | Поведение |
|----------|-----------|
| **Orphan repo** | ⚠️ "Не связан с продуктом" → клик → Editor Tab с инструкцией |
| **Product удалён на Drive** | ⚠️ "Продукт не найден на Drive" → клик → Editor Tab (та же логика) |
| **Drive offline** | Работаем с кэшем index.db, показать 🔌, skip гидратация |
| **Multi-window sync** | Не нужен. Re-scan только по кнопке 🔄. SQLite поддерживает параллельное чтение |
| **Git auth** | Полагаемся на системный git (ssh-agent, credential helper) |

#### Л. Распознавание проектов

**Правило:** проект = папка внутри `/projects/` (непосредственный родитель).

```
product/
├── projects/           ← маркер
│   ├── 260110_ai_talks ← проект ✓
│   └── 260115_refactor ← проект ✓
└── src/
    └── some_folder     ← НЕ проект
```

### 4. Настройка окружения (User Settings)

В VS Code на каждом конкретном компьютере где-то в глобальных настройках задаются такие настройки:

* `duet.business_folders`: Это корневые папки бизнесов (корневых дел / стримов). Из при первом запуске строим дерево, и если пользователь кликнет мышью на корень дерева в боковой панели то создаём multi-root workspace и открываем его. Вопрос только где именно хранить этот файл. Можон например просто в корне Google Drive. Все мои бизнес-папки также находятся в корне Google Drive (но там в корне кроме них много других папок, нам надо отфильтровать).
* `duet.data_folder`: Абсолютный путь к локальной папке типа `~/DuetData` — там будут не только `repos` но и глобальные базы данных типа DuckDB или LanceDB(в будущем).

### 5. Итог

* **Переносимость:** Вы можете сесть за любой компьютер, указать одну папку в настройках, и вся ваша «ОС Жизни» развернется по клику.
* **Безопасность:** Секреты (`.env`) и структура бизнесов всегда в облаке.
* **Скорость:** Git и Node.js работают на нативном железе без тормозов файловой системы облака.
