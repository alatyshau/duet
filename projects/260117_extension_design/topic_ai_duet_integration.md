# Интеграция AI с Duet

**Статус:** в работе

---

## МОТИВАЦИЯ

AI-агент (Claude Code, Codex и др.) работает с кодом в VS Code, но не знает контекста "жизни как ОС" — иерархии бизнесов, дел, продуктов. Когда пользователь упоминает путь типа `packages/extension/...`, агент не понимает к какому продукту это относится, где лежит репозиторий, какая структура вокруг.

Duet extension уже собирает эту информацию в SQLite базу. Нужно дать AI доступ к этим знаниям через MCP tools.

Отдельная проблема — **пути в multi-root workspace**. Когда workspace содержит два корня (git-репо и Drive-папка), возникает неоднозначность: к какому корню относится путь `packages/...`?

## НАРРАТИВ

### Откуда взялась проблема с путями

VS Code при "Copy Relative Path" выдаёт путь без имени workspace folder:
```
packages/extension/.vscodeignore
```
А не:
```
Duet.git/packages/extension/.vscodeignore
```

Человек понимает из контекста — видит `packages/`, понимает что это код, значит git-репо. AI тоже должен уметь это понимать.

### Три контекста путей

В работе с Duet есть три разных контекста интерпретации путей:

**1. Инструкции (ai-kit)**

Пути в таблицах инструкций типа `personas/socrates.md` — это ВСЕГДА относительно ai-kit root, который возвращает `get_instruction_location()`. Не от текущего файла, не от workspace — от ai-kit.

ai-kit лежит в `~/DuetData/ai-kit/`, то есть **вне workspace**.

**2. Относительные пути в workspace**

Обычные относительные пути типа `topic_xxx.md` без `./` — от текущего файла. Это стандартное поведение markdown ссылок.

**3. Пути "от корня workspace"**

Пути типа `packages/extension/src/...` — они не начинаются с `./` или `../`, но содержат узнаваемую структуру проекта. Человек понимает что это от корня репозитория.

В multi-root workspace таких корней может быть несколько. **Эвристика:** пути к коду (`packages/`, `src/`, `apps/`) относятся к git-репо, не к Drive папке.

### Идея интеграции с Duet

Duet extension уже знает всю структуру — бизнесы, дела, продукты, где какой git-репо. Эта информация в SQLite базе `~/DuetData/data/index.db`.

Если дать AI доступ к этой базе через MCP tools, он сможет:
- Узнать структуру "жизни как ОС"
- Понять что `Duet.git` в `repos/` — это репозиторий продукта Duet
- Связать Drive папку с git репо
- Правильно интерпретировать пути

### DuetData структура

```
~/DuetData/
├── ai-kit/          # Инструкции, персоны, режимы
│   ├── personas/
│   ├── modes/
│   └── ...
├── repos/           # Git-репозитории ({Product}.git/)
├── workspaces/      # Multi-root workspace файлы
├── data/
│   └── index.db     # SQLite — кэш иерархии
├── mcp/             # MCP server (копируется extension'ом)
└── config.json      # Список бизнес-папок
```

### Формулировка инструкции про пути

Как кратко и ясно объяснить AI три контекста путей? Текущий вариант:

```markdown
## Paths

### В инструкциях (ai-kit)
Пути типа `personas/...`, `modes/...` — относительно ai-kit root:
- Вызови `get_instruction_location()` для получения пути
- ai-kit находится в `~/DuetData/ai-kit/`, вне workspace

### В workspace
- `topic_xxx.md` — относительно текущего файла
- `packages/...`, `src/...` — от корня git-репо (узнаваемая структура)

### Multi-root workspace
Путь от корня → git-репо (`{Name}.git`), не Drive. Если неясно — спроси.
```

### Какие MCP tools нужны

Минимум:
- `get_duet_data_location()` — путь к DuetData
- `get_hierarchy()` — дерево сущностей из БД
- `find_entity(name)` — поиск по имени

Возможно в будущем:
- Query по типу (`get_products()`, `get_businesses()`)
- Поиск по пути (`find_entity_by_path()`)

### Фаза 3: Bootstrap инструкции для AI агентов

#### Проблема "курицы и яйца"

MCP Server предоставляет tools (`get_instruction_location`, `get_hierarchy`...), но AI не знает:
- Что эти tools существуют
- Зачем их вызывать
- Как использовать результат

**Нужны "bootstrap" инструкции** — базовый промпт который говорит AI как работать с Duet.
