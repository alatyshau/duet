# AI Kit v2: Архитектура будущего

**Статус:** черновик

---

## МОТИВАЦИЯ

Текущая структура ai-kit складывалась органически: появились персоны, потом режимы, потом stances, потом skills. Границы между ними размыты — что-то повторяется, что-то непонятно куда класть.

Нужна чистая архитектура, где каждый компонент имеет ясное назначение и место.

Параллельно — все скрипты (timestamp, backlog_updater, ai_doc_updater и др.) разбросаны по разным местам. Хочется единый бэкенд, библиотека операций доступная через MCP.

## НАРРАТИВ

### Текущее состояние ai-kit

```
ai-kit/
├── core_instructions.md      # Ядро + много всего
├── core_instructions_short.md
├── personas/                  # Агенты (Сократ, Ариадна...)
├── modes/                     # Операции (PLANNING, EXECUTE...)
├── stances/                   # Стили мышления (dialectic, pragmatic...)
├── skills/                    # Технические знания (python, typescript...)
├── schemas/                   # Форматы файлов
└── workflows/                 # solo, pair, sddg
```

**Проблемы:**
- `core_instructions` содержит и красные линии, и глоссарий, и таблицы — много всего
- Stances и Skills пересекаются концептуально
- Часть персон — это скорее "стиль работы", а не отдельный агент
- Нет единого места для "каким я хочу видеть AI"

### Идея новой архитектуры

**Skills становятся центральным понятием** — это не только технические знания, но и:
- Как разговаривать с человеком
- Доменное знание о Duet
- Стиль мышления (бывшие stances)
- Дистиллированные аспекты персон

**Core остаётся минимальным:**
- Красные линии
- Базовые правила
- Загрузка skills по запросу

**Персоны = агенты:**
- Полноценные специализации
- Используют skills как building blocks
- Аналог агентов в Claude Code

**Режимы = операции:**
- Что сейчас делаю (PLANNING, EXECUTE, REVIEW)
- Определяют права доступа к файлам
- Не меняются — работают

### Новая структура

```
ai-kit/
├── core.md                    # Минимум: красные линии, загрузка skills
│
├── skills/                    # Всё доменное знание
│   ├── communication.md       # Как разговаривать
│   ├── duet-ecosystem.md      # Знание о Duet (из Ариадны)
│   ├── dialectic.md           # Бывший stance
│   ├── pragmatic.md           # Бывший stance
│   ├── python.md              # Технический
│   ├── typescript.md          # Технический
│   └── ...
│
├── personas/                  # Агенты (остаются)
│   ├── socrates.md
│   ├── hephaestus.md
│   └── ...
│
├── modes/                     # Операции (остаются)
│   ├── planning.md
│   ├── execute.md
│   └── ...
│
└── schemas/                   # Форматы (вспомогательное)
    ├── topic_file.md
    └── ...
```

### Python MCP Backend

Все скрипты уходят в единый MCP сервер на Python:

```
DuetData/
└── mcp-server/               # Python backend
    ├── server.py             # MCP server
    ├── tools/
    │   ├── timestamp.py
    │   ├── hierarchy.py      # Работа с БД
    │   ├── secretary.py      # Архивация чатов
    │   ├── backlog.py        # Управление backlog
    │   └── ...
    └── db/
        ├── sqlite.py         # Иерархия
        ├── duckdb.py         # Аналитика (будущее)
        └── lancedb.py        # Embeddings (будущее)
```

AI и Extension общаются с этим бэкендом через MCP.

## ОТКРЫТЫЕ ВОПРОСЫ

### Что дистиллировать из персон в skills?

Персоны содержат полезное знание, которое может быть skill'ом:
- Ариадна → `duet-ecosystem.md` (знание о Duet)
- Гермес → `documentation.md` (как писать документацию)?
- Сократ → часть уже в `dialectic.md`

Какие персоны останутся как полноценные агенты, а какие станут skills?

### Как организовать skills?

Варианты:
1. **По типу**: technical/, communication/, thinking/
2. **Плоский список**: все в одной папке
3. **По частоте**: core-skills/ vs optional-skills/

### Миграция существующих инструкций

Как мигрировать без потери функциональности:
- [ ] Выделить красные линии в core.md
- [ ] Перенести stances в skills
- [ ] Дистиллировать персоны
- [ ] Обновить ссылки
