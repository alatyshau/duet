## Scope сессии

**Одна сессия (чат) = одна папка.** Бери следующую необработанную папку из таблицы прогресса. После завершения папки — стоп. Не начинай следующую.

---

## Процесс

### Как работать с файлами в папке

1. Прочитай `index.md` папки (если есть) и перечисли файлы
2. Читай файлы **по одному** (или очевидную группу), сверяй с реальным продуктом (spec/, код)
3. Дай **отчёт** — что снято, что живое. Один вопрос/решение за раз, не перегружать
4. Получи **одобрение**
5. Только после одобрения — перенеси, обнови index.md (архива и исходной папки), обнови таблицу прогресса в этом файле

### Что НЕ делать

- **Не читай файлы следующей папки** — это другая сессия, потратишь контекстное окно впустую
- **Не действуй без одобрения** — никаких mv, никаких обновлений index.md до явного "да"
- **Не давай огромных отчётов** — размер определяется когнитивной нагрузкой человека
- **Не забывай обновлять этот файл** — таблица прогресса и журнал должны быть актуальны

### Батчинг

Очевидно завершённые файлы можно обрабатывать по несколько за раз. Останавливаться когда есть вопрос, неясность, или что-то интересное — не перегружать человека.

### После завершения папки

Обнови журнал ревизии (внизу этого файла). Стоп. Не начинай следующую папку.

## Принцип Aufheben

Для каждого файла: все ли идеи **сняты** в текущем продукте? (в гегелевском смысле — сохранены, преодолены, подняты на новый уровень)

**Если всё снято** → файл целиком в архив. Сохраняй содержание с мясом (суть, решения, контекст).

**Если не всё снято** → файл распадается на два:
- `ARCHIVE/.../260220_xxx.md` — архив снятой части
- Оригинал заменяется на **бэклог**: только живые идеи, нерешённые вопросы

> **Главный приоритет — поиск живого.** Сделанное убираем. Несделанное — ловим и формулируем.
