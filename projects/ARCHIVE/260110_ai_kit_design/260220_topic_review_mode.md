# Review Mode — спецификация

**Статус:** Снято → `ai-instructions/modes/review.md`
**Откуда:** `260110_ai_kit_design/topic_review_mode.md`

---

## Суть

Формализация режима REVIEW — ревью работы одного агента другим. Введён при ревью шага 4 в topic_base_instructions.

## Ключевые решения

**Reviewer = co-author.** Полная ответственность за артефакт после ревью. Не "файл создан" — а понять интеграцию, пути, зависимости.

**Бинарный вердикт:** ПРИНЯТО (0 замечаний) или НЕ ПРИНЯТО (≥1). "ПРИНЯТО + рекомендации" — запрещено. Все замечания равноценны, нет деления на блокеры/минорные.

**Ревьювер не управляет статусом шага** — только замечания и вердикт. Не спрашивает "перевести в DONE?"

**Нумерация ревью** (`#1`, `#2`, ...) для трассируемости. Статусы замечаний: `⚠ ОТКРЫТО` → `✓ ИСПРАВЛЕНО`.

**Разные персоны — разный фокус:** Дедал (архитектура), Сократ (зачем?), Локи (а что если?).

**REVIEW (режим) ≠ IN_REVIEW (статус шага).** Режим — что агент делает. Статус — техническая метка.

## Уроки из практики

1. Reviewer = co-author (пропустил сломанную интеграцию → урок)
2. Инструкции ≠ нарратив (в артефактах — императив, история — в топиках)
3. Чистый формат ревью: что проверено (таблица) + замечания + вердикт

## Профиль компетенций

Системное мышление, спецификационный стиль, threat-model для AI, дизайн интерфейса для агентов, reviewer = co-author.
