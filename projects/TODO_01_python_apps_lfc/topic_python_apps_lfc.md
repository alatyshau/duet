# Python Apps Lifecycle Management

**Статус:** бэклог

---

## МОТИВАЦИЯ

Duet Host уже сидит в трее и управляет Backend. Естественное развитие — управлять любыми Python-приложениями пользователя оттуда же: торговые роботы, анализаторы новостей, составители отчётов.

Архитектура уже подготовлена — типы `AppInfo`/`ProcessInfo`/`ProcessStatus` обобщены, `core/apps.ts` содержит placeholder для динамического реестра.

Источник: `ARCHIVE/260220_duet_mvp/260220_ход_работы.md` строка 5.

## НАРРАТИВ

### Текущее состояние (260224)

Host управляет одним builtin-приложением (Duet Backend):
- Реестр: `BUILTIN_APPS` в `core/apps.ts`
- Lifecycle: `startBackend()` / `stopBackend()` / `checkHealth()` в `core/backend.ts`
- UI: Sidebar → секция "Приложения" → "Duet Backend" → AppPage с process cards

Типы уже обобщены (`AppInfo` не привязан к Backend), но вся реальная логика — под Backend.

### Идея из ход_работы.md

> Добавить возможность запускать и управлять любыми другими моими питон-приложениями из трея (трейдинг-роботы, анализаторы новостей, составители отчётов, и т.п.). Ещё более простая идея: в начале переделать UI сделать табку для Настроек и табку для Приложений в боковой панели.

## ОТКРЫТЫЕ ВОПРОСЫ

### 1. Что такое "Python-приложение" в контексте Duet Host?

Варианты:
- **a)** Директория с entry point (`main.py` или настраиваемый) + необязательный `requirements.txt` / venv
- **b)** Описание в конфиг-файле (`apps.json`) с путём к скрипту
- **c)** Любой `.py` скрипт, указанный пользователем

Вопрос: как выглядят реальные приложения пользователя? Папка с venv? Один скрипт? Что-то третье?

### 2. Где живут приложения?

Варианты:
- В `DuetData/apps/` (стандартная директория)
- В произвольном месте (пользователь указывает абсолютный путь)
- Обнаруживаются автоматически из известной директории

### 3. Как регистрировать приложение?

Варианты:
- Ручное редактирование конфига (`DuetConfig/apps.json`)
- UI-визард в Host (кнопка "Добавить приложение")
- Сканирование директории

### 4. Что входит в lifecycle?

Минимум:
- Start / Stop / Restart

Расширенное:
- Health check (HTTP endpoint? Просто "процесс жив"?)
- Auto-start при запуске Host
- Просмотр логов (stdout/stderr)
- Перезапуск при падении (watchdog)

### 5. UI: что значит "табки Настройки и Приложения"?

Текущий Sidebar: Установка → Приложения → AI Агенты (плоская структура).

Варианты перестройки:
- **a)** Два таба вверху окна (Настройки | Приложения), каждый со своим содержимым
- **b)** Sidebar остаётся, но с чётким разделением на две зоны
- **c)** Установка и AI Агенты → таб "Настройки"; Приложения → таб "Приложения"

### 6. Tray-интеграция

Нужно ли управление из tray-меню? Например:
- Подменю с каждым приложением
- Быстрый Start/Stop без открытия окна
- Индикатор статуса в tray (сколько процессов запущено)
