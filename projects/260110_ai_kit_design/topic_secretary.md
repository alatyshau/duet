## МОТИВАЦИЯ

### Откуда возникла потребность (философская база)

Сессия началась с задачи "создать инструкции для SoftEng". Но быстро стало ясно — проблема глубже. Дело не в конкретной роли. Дело в том, **как** мы общаемся.

[ALA] обнаружил паттерн: AI торопится, прилипает к решениям, выдаёт "вердикты" вместо того чтобы слушать и накапливать. А сам [ALA] — Субъект, Ловец Различений — работает иначе: набрасывает сумбурно, ловит различения, переключается между темами. Ему нужен не исполнитель. Ему нужен **секретарь**.

### Что значит "секретарь"

Секретарь — не клерк который записывает под диктовку. Это:

> **Секретарь мотивации и рефлексии. Секретарь диалектики.**

Его задача:
- Формулировать мысли [ALA], наполняя их ясностью
- Систематизировать сумбур
- Удерживать нити разговора
- Разруливать противоречия
- Записывать в файлы так, чтобы контекст был восстановим

### Распределённое мышление

Это не "AI помогает человеку". Это симбиоз двух интеллектов с разными сильными сторонами:

| | ALA | Secretary |
|---|---|-----------|
| Режим | Набросок, различение, скачок | Структура, ясность, удержание |
| Продукт | Сырые идеи | Оформленный контекст |
| Слабость | Сумбурность, рассеянность | Прилипание к решениям |

Вместе — сильнее чем по отдельности.

### Зачем функция /secretary

В ходе диалога стало ясно: философия секретарства должна быть реализована как workflow — механизм периодической выгрузки контекста из чата в файлы. Похоже на /compact, но с другой целью.

### Проблема которую решаем

- `/compact` сжимает контекст для AI (summary в памяти)
- Нет аналогичного механизма для персистентных артефактов (файлов)

Нужна функция которая:
1. Оценивает состояние тем (reassessment)
2. Предлагает рефакторинг если нужен
3. Выгружает контекст в topic_*.md файлы

### @turn(260112_014953M) — Уточнение сути /secretary

Главная задача /secretary:

> **Убедиться, что в истории чата не осталось ни единой мысли, не перенесённой в чат-папку.**

Это **архивация чата на диск** — чтобы можно было:
- Начать новый чистый чат
- Не бояться compaction
- Восстановить контекст из файлов

**Правила:**
- Сохраняем только **актуальные** мысли
- Отменённое — только если ценно для нарратива (диалектика формирования выводов)
- Работаем на уровне **всей чат-папки**, не одной темы
- Отлипаем от текущего фокуса, видим общую картину

**Когда вызывать:**
- **Перед execute** — чтобы архивировать накопленный контекст
- После длинного диалога — когда много мыслей в чате
- Перед закрытием чата — чтобы ничего не потерять

**Создание новых тем:**
- Обычно новые темы создаются в режиме DIALOGUE
- Но /secretary **может** создать новую тему, если это необходимо для полноты архивации
- Это исключение, не норма

**Режим:** SECRETARY (отдельный режим работы агента)

### @turn(260112_015624M) — Метод работы /secretary

**/secretary — тяжёлый workflow**, похож на "extra long thinking":

**Метод обработки:**
1. Физически весь текст до checkpoint — как единый массив
2. Проход по КАЖДОМУ сообщению (и от user, и от agent)
3. Для каждого: что нового? записано ли?
4. Пограничный кейс: последнее сообщение user (перед /secretary) — тоже содержит мысли!

**Требует перепроверок:**
- После первого прохода — проверить не пропущено ли что-то
- Особенно сообщение с запросом /secretary (там могут быть мысли!)

**Формат отчёта (таблица прохода):**

```markdown
| # | От | Суть | Записано? |
|---|-----|------|-----------|
| 1 | user | краткое описание мысли | ✅ в topic_xxx.md |
| 2 | agent | что сделал | — (действие) |
| 3 | user | следующая мысль | ✅ / ❌ |
...
```

Таблица помогает:
- Визуализировать прогресс
- Не пропустить сообщения
- Показать пользователю что обработано

**Завершение:**
- Вывести checkpoint в чат
- После checkpoint — возврат в DIALOGUE
- Дальнейшее обсуждение — это уже не SECRETARY

## ВЫХОДЫ

### Спецификация /secretary

**Триггер:** Пользователь вызывает `/secretary`

**Алгоритм:**

```
1. Найти точку старта
   - Искать последний @secretary_checkpoint(TIMESTAMP) в чате
   - Или искать compaction/summary маркер (fallback)
   - Если ничего — от начала чата

2. Reassessment
   - Прочитать index.md
   - Оценить: нужен ли рефакторинг тем?

3. Если рефакторинг нужен:
   - Предложить план рефакторинга
   - Ждать апрув
   - Выполнить рефакторинг index.md

4. Для каждой темы в index.md:
   - Если topic_*.md не существует → создать
   - Если существует → обновить (append, не overwrite)

5. Обновить index.md с актуальными резюме

6. Вывести checkpoint в ЧАТ (не в файл!)
```

### Формат checkpoint

**Выводится в чат как H1:**

```markdown
# @secretary_checkpoint(260111_031913M)
```

Рендерится как заголовок для лучшей читаемости в истории чата.

**Почему в чат, а не в файл:**
- После /compact маркер сохранится в summary
- AI увидит его в истории чата при следующем вызове
- Не засоряет файлы служебной информацией

**Regex для парсинга:** `@secretary_checkpoint\((\d{6}_\d{6}[A-Z])\)`

### Структура topic-файла

См. [topic_document_structure.md](topic_document_structure.md)

5 секций H2:
1. МОТИВАЦИЯ
2. ССЫЛКИ
3. НАРРАТИВ
4. ВЫХОДЫ
5. ПЛАН ВНЕДРЕНИЯ

### Отличие от /compact

| Аспект | /compact | /secretary |
|--------|----------|------------|
| Цель | Сжать контекст для AI | Выгрузить в файлы для человека |
| Результат | Summary в памяти | Персистентные topic_*.md |
| Когда вызывать | Автоматически / вручную | Вручную |
| Мутация | Заменяет историю | Append-only |
