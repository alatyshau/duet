### @turn(260123_1200M) — Skills и Stances

Обнаружили недостающие оси:

| Ось | Вопрос | Примеры |
|-----|--------|---------|
| Персона | WHO | Сократ, Гефест |
| Режим | WHAT | DIALOGUE, EXECUTE |
| **Skill** | EXPERTISE | python, typescript, lean |
| **Stance** | HOW TO THINK | dialectic, pragmatic |

**Ключевое уточнение:** Skill ≠ режим.
- code-reviewer — это режим REVIEW
- Skill = предметная экспертиза (знания из "Effective Java", "Fluent Python")

**Skill vs Stance — разница:**
- Skills комбинируются (`@skill(python) + @skill(testing)`)
- Stance переключается по ходу чата (исследование → dialectic, реализация → pragmatic)
- У Stance может быть default

### @turn(260124_1825M) — Калибровка use cases + 5 принципов каркаса

**Калибровка на 4 кейсах:**

| Кейс | Сложность | Каркас нужен? |
|------|-----------|---------------|
| data_curator_pkm (IDE) | LOW-MED | Частично |

**Ключевой инсайт:** Без явного `stance=dialectic` агент скатывается в "режим исполнителя".

**5 принципов каркаса (решение):**

| # | Принцип | Следствие |
|---|---------|-----------|
| 1 | Каркас нужен | Не опциональный, а базовый |
| 2 | Чёткое различение | modes ≠ stances ≠ skills ≠ workflows |
| 3 | Богатое разнообразие | Десятки вариантов каждого |
| 4 | Гайды как "шорткаты" | Запоминаемость через практику |
| 5 | Эргономичный синтаксис | `!поза=ДИАЛ` вместо `@stance()` |

**Новый синтаксис аннотаций:**

```
!поза=ДИАЛ !опыт=ИИА
```

Выбор `!` обусловлен:
- Доступность в RU раскладке (Shift+1)
- `@` и `/` тригерят всплывающие окна IDE
- Универсальность для Windows-пользователей

**Доступный алфавит:**
- Маркеры: `!` `?`
- Связки: `=` `:`
- Группировка: `( )`
- Слова: `-` `_`

**Методологический принцип:**
> Имена файлов, метаданные — 0 доверия. Только глубокий анализ контента.

**Фундаментальный вопрос проекта:**
> Насколько практичен каркас (modes/stances/skills/workflows) для ВСЕХ use cases?

Не только для R&D, но и для:
- Простых задач (PDF→MD, data curation)
- Задач которые начинаются просто, но перетекают в сложные (анализ крови → план изменений образа жизни)
- PKM-операций по мере переноса жизни из Notion в md-файлы

**Спектр задач:**
```
Простое                                          Сложное
──────────────────────────────────────────────────────────►
[распознать PDF]  [Q&A]  [отладка]  [планирование]  [R&D]
```

**Паттерн Web→IDE:**
- Web (Claude.ai) — большое контекстное окно, широкое мышление
- IDE (VS Code) — execution, archiving, persistence
- Нужен **IMPORT mode** — экстракция продуктов из web-чата в topic-файлы

#### Web-специфичные паттерны

**Типы web-сессий:** research, learning, architecture, trading/analysis, health_planning, debugging, brainstorm

**Паттерны пользователя:**
- **Progressive disclosure** — раскрытие контекста слоями
- **Challenge & Verify** — проверять "зачем?"
- **Audit My Choice** — пользователь находит, AI валидирует
- **Artifact-centric** — чат → итоговый документ
- **Rubber ducking** — AI для экстернализации мышления

#### Критические инсайты

1. **Defensive prompting** — AI игнорирует мягкие инструкции, нужны явные ⚠️ запреты
2. **Binary verdict** — ПРИНЯТО XOR НЕ ПРИНЯТО (никаких "рекомендаций")
3. **"Шаг назад"** — после изменений перечитать файл целиком
4. **Batch size** — меньше = лучше качество (5 файлов / 3 секции)
5. **State machine violations** — частая ошибка агентов
6. **CurrentStepWork.md** — протокол обмена между агентами
7. **"Зачем?" как quality gate** — каждое предложение проверяется
