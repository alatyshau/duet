## МОТИВАЦИЯ

### Зачем этот документ

Документирует решения по организации пакета `packages/ai-kit/` — набора инструментов для работы с AI.

### Проблема которую решаем

Был пакет `ai-roles` с узким названием, не отражающим полный scope:
- Не только роли, но и инструкции
- Не только шаблоны, но и скрипты, workflows, схемы

## НАРРАТИВ

### История идеи модульности (из 260109_roles)

> [ALA] создай packages/ai-roles/ — туда templates (secretary.md.j2, principal.md.j2...), _includes (red_lines.md, chat_doc.md), build.py. Результат пуляется в .ai/roles.

Идея: модульность ролей. Вместо монолитных .md файлов — шаблоны Jinja2 с переиспользуемыми включениями. Это позволит:
- Общие секции (red lines, chat doc format) в одном месте
- Версионирование шаблонов
- Автоматическая сборка в .ai/roles/

[Claude:Secretary] Jinja2 (.j2) — хороший выбор для шаблонизации. `_includes/` — конвенция из Jekyll/Hugo для partials.

> [ALA] packages/ai-roles/scripts — это личные скрипты ролей, поэтому логично туда их двинуть. ai-roles на втором этапе уедут в отдельный репо и будут дёргаться через submodule. У меня 10 проектов куда это всё надо внедрить.

[Claude:Secretary] Понял! Это переиспользуемый модуль для 10+ проектов. Скрипты keeper — это часть инфраструктуры AI-ролей, поэтому они едут вместе.

### @turn(260111_0355M) — Переименование ai-roles → ai-kit

Название `ai-roles` не отражало scope. Пакет содержит:
- Инструкции (INSTRUCTIONS.md.j2)
- Роли (templates/roles/)
- Скрипты (scripts/)
- Схемы (будут)
- Workflows (/secretary, /keeper)

**Решение:** `ai-kit` — набор инструментов, комплект.

### @turn(260111_0401M) — Исправление ROOT_DIR

После переноса в `packages/ai-kit/` скрипты генерили файлы не туда (в `packages/ai-kit/.ai/` вместо корневой `.ai/`).

**Решение:** `find_repo_root()` ищет `.git` для определения корня репозитория.

### @turn(260111_0432M) — Стандартизация _DOC полей

Массовая замена во всех JSON файлах и Python скриптах:
- `КТО_ИСПОЛЬЗУЕТ` → `ИСПОЛЬЗОВАНИЕ`
- Добавлено поле `СПЕКА` со ссылкой на схему (`.ai/schemas/*.json.md`)
- Обновлены устаревшие пути `packages/ai-roles/` → `packages/ai-kit/`

**Затронуто:** 12 JSON, 5 Python, 3 схемы.

### @turn(260111_0449M) — IGNORED_PREFIXES для Keeper

Добавлена фильтрация `.ai/` и `drafts/` из backlog Keeper:
- **ai_git_updater.py**: `IGNORED_PREFIXES` + очистка legacy записей
- **ai_doc_updater.py**: `KEEPER_IGNORE_PREFIXES` (не добавлять в missing_docs)

**Результат:**
- WORKSPACE_MAP.md показывает `[MISSING DOCS!]` для .ai/ файлов
- Backlog Keeper не содержит .ai/ и drafts/

**Баг исправлен:** Variable shadowing `prefix` в for-цикле ломал отступы дерева. Заменено на `any()`.

### @turn(260111_050539M) — Разделение source/destination

Уточнено разделение папок:

| Папка | Режим | Использование |
|-------|-------|---------------|
| `packages/ai-kit/` | Разработка | Исходники — templates, scripts |
| `.ai/` | Использование | Сгенерированные артефакты для AI |

**Ключевые инсайты:**
- AI **никогда** не читает инструкции из `packages/ai-kit/`. Только из `.ai/`.
- AI **пишет код** в `packages/ai-kit/` когда работает в режиме разработки.
- Любая роль может писать код — это не запрет, а вопрос миссии.

### @turn(260112_014515M) — Планируемый рефакторинг templates/

Запланирована реструктуризация `templates/`:
- `_includes/` → `instructions/` с подпапками по секциям
- Принцип: секция без подсекций = файл, с подсекциями = папка

Детали см. в [topic_base_instructions.md](topic_base_instructions.md) → ВЫХОДЫ → Структура шаблонов.

### @turn(260112_121724M) — Документация для пользователей

АЛ: нужна пользовательская документация для ai-kit — "как пользоваться".

**Предложенная структура:**
- `packages/ai-kit/README.md` — getting started, карта документов
- `packages/ai-kit/docs/USAGE.md` — полный user guide: роли, режимы, workflows, как генерировать
- `packages/ai-kit/docs/GLOSSARY.md` или часть USAGE — базовый тезаурус: проект vs дело, продукт, предприятие

**Ключевое различение:**
- Базовые инструкции = "конституция" для агента (что агент читает)
- User guide = документация для человека (как человек пользуется ai-kit)

## ВЫХОДЫ

### Структура пакета

```
packages/ai-kit/
├── build.py              # Сборка ролей
├── README.md
│
├── scripts/              # Скрипты автоматизации
│   ├── timestamp.py      # Генерация timestamp
│   ├── keeper_utils.py   # Утилиты для keeper_state
│   ├── ai_doc_updater.py
│   ├── ai_git_updater.py
│   └── backlog_updater.py
│
└── templates/            # Jinja2 шаблоны
    ├── INSTRUCTIONS.md.j2  # Базовые инструкции
    ├── roles/              # Шаблоны ролей
    └── _includes/          # Переиспользуемые части
```

### Ключевые решения

| Решение | Причина |
|---------|---------|
| `ai-kit` вместо `ai-roles` | Отражает полный scope: инструкции + роли + скрипты + workflows |
| `find_repo_root()` | Скрипты работают независимо от расположения пакета |
| Переменная `AI_KIT_OUTPUT_DIR` | Гибкость при сборке |

### Документация для пользователей (планируется)

| Файл | Аудитория | Содержание |
|------|-----------|------------|
| `README.md` | Новый пользователь | Что это, для кого, quick start |
| `docs/USAGE.md` | Пользователь | Роли, режимы, workflows, генерация |
| `docs/GLOSSARY.md` | Все | Тезаурус: проект, дело, продукт, предприятие |
