# Предложение по решению проблемы: Context-as-Code (Контекст как Код)

## 1. Предлагаемое решение

Для решения проблем потери контекста, непредсказуемости и отсутствия переносимости (R1, R3, R9) я предлагаю архитектурный подход **"Context-as-Code" (Контекст как Код)**, реализованный через **файловую систему**.

### Архитектура и Компоненты

Вместо того чтобы полагаться на скрытое состояние чата или векторную базу данных IDE, мы делаем **файловую систему** единственным источником истины (Source of Truth) для контекста взаимодействия.

**Компоненты:**

1.  **Репозиторий Контекста (`.ai-context/` или `.context/`)**:
    Специальная директория в корне проекта, содержащая структурированные Markdown/YAML файлы. Она версионируется в Git вместе с кодом.
    *   `goals.md`: Долгосрочные цели проекта и текущей сессии.
    *   `memory.md`: "Выученные" уроки, стиль кодирования, специфичные для проекта решения (R1).
    *   `roadmap.md`: Статус текущих задач (To-Do, In Progress, Done) — для Инкрементальности (R4).
    *   `active_state.md`: "Оперативная память" — текущий фокус внимания, краткая сводка последнего обсуждения.

2.  **Менеджер Режимов (Mode Enforcer - R2, R3)**:
    Набор системных промптов (System Prompts), которые жестко переключают поведение LLM. Агент читает файлы контекста и инструкцию режима перед каждым ответом.
    *   **Режим "Архитектор" (Dialogue Mode)**:
        *   *Цель*: Понять задачу, обновить `roadmap.md` и `active_state.md`.
        *   *Ограничение*: Не имеет права писать код реализации. Только псевдокод или структуры данных. Задает вопросы (R6).
    *   **Режим "Исполнитель" (Coding Mode)**:
        *   *Цель*: Реализовать задачу из `active_state.md`.
        *   *Ограничение*: Строгий TDD. Пишет тесты -> пишет код. Не меняет архитектуру без разрешения.
    *   **Режим "Ревьюер" (Audit Mode)**:
        *   *Цель*: Сравнить код с `goals.md` и стандартами.
        *   *Поведение*: Критичное, "адвокат дьявола" (R7).

3.  **Агент-Синхронизатор**:
    Плагин или скрипт, который автоматически добавляет содержимое файлов `.context/` в контекстное окно LLM при каждом запросе и обновляет эти файлы на основе ответов LLM (если разрешено режимом).

### Как это решает проблемы:

*   **Управляемость и Потеря контекста**: Контекст не исчезает при закрытии чата. Он лежит в файлах. Новый чат начинается с чтения `active_state.md` (R1).
*   **Непредсказуемость**: Режимы (System Prompts) запрещают "Исполнителю" фантазировать, а "Архитектору" — писать говнокод. Границы четко очерчены (R2).
*   **Переносимость и Мульти-агентность (R9)**: Вы можете начать задачу с Claude 3.5 Sonnet (в режиме Архитектора), сохранить план в `roadmap.md`, и продолжить с GPT-4o (в режиме Исполнителя). Агенты синхронизируются через файлы, а не через проприетарную историю чата.

## 2. Существующие решения

На данный момент идеального коробочного решения нет, но есть инструменты, реализующие части этого подхода:

1.  **Cursor (с правилами `.cursorrules`)**:
    *   *Что есть*: Позволяет задать глобальный контекст и правила для проекта.
    *   *Чего нет*: Динамического переключения режимов, структурированного ведения памяти (всё сваливается в один файл или чат).

2.  **Cline (ранее Claude Dev) / Roo Code**:
    *   *Что есть*: Продвинутая работа с файлами, возможность использовать custom instructions (режимы). Поддерживает создание файлов для памяти (`.clinerules`).
    *   *Перспектива*: Наиболее близок к реализации "Context-as-Code", так как активно работает с файловой системой и MCP (Model Context Protocol).

3.  **Aider**:
    *   *Что есть*: "Chat with your code". Отлично держит контекст через `ctags` и карту репозитория.
    *   *Чего нет*: Явного разделения на режимы планирования/реализации. Склонен сразу бросаться в бой.

4.  **Model Context Protocol (MCP)** (от Anthropic):
    *   Стандарт, позволяющий подключать внешние источники данных (память, БД) к LLM. Это *фундамент* для построения описанной системы.

## 3. Критика и дополнения

*   **Риск "Бюрократии" (Critique R5)**:
    Подход с файлами контекста может стать тяжеловесным для мелких задач ("fix typo"). Требуется "Легкий режим" (Quick Mode), который игнорирует `roadmap.md` и просто правит файл. Нельзя заставлять пользователя обновлять документацию ради исправления запятой.
*   **Context Pollution**:
    В формулировке проблемы упущена проблема "зашумления" контекста. Если файлы `.context/` разрастутся, они перестанут влезать в окно контекста или начнут сбивать модель. Необходим механизм **архивации** устаревшего контекста (перенос из `active_state.md` в `archive/log_2024.md`).
*   **R7 (Честность AI)**:
    Это требование сложно гарантировать архитектурно. Модели обучаются быть "полезными" (helpful), что часто означает "соглашаться с пользователем". Для реализации "честного партнера" требуются специально настроенные System Prompts, явно поощряющие критику.
