## 1. Моё предложение

### Ключевой инсайт

Корень проблемы — **смешение эфемерного (чат) и персистентного (знания)**. Чат — это интерфейс взаимодействия, а не хранилище знаний. Решение: разделить эти слои.

### Компоненты

#### 1. Project Memory (`.mind/` директория)

**Формат:** YAML + Markdown файлы в репозитории проекта.

**Почему файлы:**
- Версионируются через Git
- Читаемы человеком и AI
- Переносимы между клиентами
- Редактируемы напрямую

**Структура:**

```yaml
# .mind/context.yaml
project:
  name: "My Trading Bot"
  phase: "research"  # research → design → implementation → testing

active_threads:
  - id: "strategy-validation"
    status: "exploring"
    summary: "Проверяем гипотезу о momentum на 15-минутках"

  - id: "backtesting-framework"
    status: "blocked"
    blocker: "Нужно определиться с форматом данных"

focus:
  current_thread: "strategy-validation"
  parking_lot:  # "отложенные" мысли
    - "Потом посмотреть альтернативные источники данных"
    - "Идея: комбинировать с sentiment analysis"
```

```yaml
# .mind/modes.yaml
modes:
  explore:
    description: "Исследование, сбор информации"
    ai_behavior:
      - "Задавай уточняющие вопросы"
      - "Не предлагай решения, пока не попросят"
      - "Суммируй найденное"
    allowed_actions: [read, search, ask]

  discuss:
    description: "Выработка понимания"
    ai_behavior:
      - "Отражай своё понимание"
      - "Указывай на противоречия"
      - "Предлагай формулировки"
    allowed_actions: [read, suggest]

  plan:
    description: "Планирование изменений"
    ai_behavior:
      - "Предлагай конкретные шаги"
      - "Один шаг = одно изменение"
      - "Жди подтверждения"
    allowed_actions: [read, plan]

  execute:
    description: "Выполнение плана"
    ai_behavior:
      - "Делай ровно то, что согласовано"
      - "Останавливайся при неясности"
    allowed_actions: [read, write, run]

  review:
    description: "Проверка результатов"
    ai_behavior:
      - "Проверяй соответствие плану"
      - "Ищи проблемы"
      - "Не защищай свою работу"
    allowed_actions: [read, comment]
```

#### 2. Context Orchestrator

Middleware между чатом и AI, который:

**a) Собирает контекст:**
```
[режим] + [активный тред] + [релевантные decisions] + [сообщение]
→ prompt для AI
```

**b) Извлекает ценное из ответов:**
- Новые решения → `.mind/decisions/`
- Новые понятия → `.mind/concepts/`
- Открытые вопросы → обновляет `threads/`

**c) Управляет режимами:**
- Отслеживает текущий режим
- Инжектит поведенческие инструкции
- Ограничивает действия AI

#### 3. Thread Manager

Решает проблему "много тем в одном чате":

```
/thread list              # показать активные темы
/thread switch backtesting  # переключить фокус
/thread park "посмотреть позже"  # отложить мысль
/thread close strategy-v1 --extract  # закрыть, извлечь ценное
```

Каждый thread — отдельный файл:
```yaml
# .mind/threads/strategy-validation.yaml
id: "strategy-validation"
created: "2026-01-15"
status: "active"

goal: "Проверить работает ли momentum стратегия на 15м"

history:  # сжатая история, не полный чат
  - "Начали с гипотезы: momentum > 2% за 15м = сигнал"
  - "Нашли что 2% слишком агрессивно, тестируем 1.5%"
  - "Проблема: много ложных сигналов ночью"

open_questions:
  - "Фильтровать ночные часы или адаптировать порог?"

artifacts:
  - path: "research/momentum-analysis.ipynb"
  - path: "src/strategies/momentum_v1.py"
```

#### 4. Extraction Pipeline

При закрытии чата/треда — полуавтоматическое извлечение:

```
AI анализирует историю чата
        ↓
Предлагает:
  - Decisions (что решили)
  - Concepts (новые термины/понятия)
  - Open questions (что осталось)
        ↓
Human ревьюит и подтверждает
        ↓
Сохраняется в .mind/
```

### Режимы работы — подробнее

| Режим | Метафора | AI делает | AI НЕ делает |
|-------|----------|-----------|--------------|
| **Explore** | Исследователь | Ищет, читает, задаёт вопросы | Не предлагает решения |
| **Discuss** | Собеседник | Отражает понимание, уточняет | Не действует |
| **Plan** | Архитектор | Предлагает конкретные шаги | Не выполняет |
| **Execute** | Исполнитель | Делает согласованное | Не импровизирует |
| **Review** | Критик | Ищет проблемы, честно оценивает | Не защищает свою работу |

**Переключение явное:**
```
/mode explore    # или через UI
```

**AI видит режим и адаптируется:**
```
[Mode: EXPLORE]
Инструкция: Ты в режиме исследования. Задавай вопросы,
собирай информацию. Не предлагай решения, пока не переключат
в режим discuss или plan.
```

### Мульти-агентность

**Сценарий:** Два AI работают над одним проектом параллельно.

**Как это работает:**
1. Оба читают `.mind/context.yaml` — синхронизация
2. Каждый работает над своим тредом
3. Записывают результаты в `.mind/threads/`
4. При конфликте — человек решает

```
Claude (Thread: architecture)     GPT (Thread: data-format)
        │                                │
        ├────────────────────────────────┤
        │     .mind/ (shared state)      │
        └────────────────────────────────┘
```

**Координация через файлы:**
- `threads/*.yaml` — кто над чем работает
- `decisions/*.yaml` — что уже решено (все должны знать)
- Git для merge конфликтов

## 3. Критика формулировки

### Что важного упущено

1. **Стоимость переключения контекста**
   - Режимы — это overhead. Для quick fix не нужен explore→discuss→plan→execute
   - Нужен "быстрый режим" для тривиальных задач

2. **Доверие и верификация**
   - Как понять что extraction правильный?
   - AI может ошибаться при извлечении "ценных мыслей"

3. **Onboarding**
   - Кривая обучения для новых режимов
   - Пользователь должен понимать когда какой режим

4. **Интеграция с существующим workflow**
   - Как это живёт вместе с Git workflow?
   - Нужны ли хуки?

### Какие требования кажутся вторичными

| Требование | Оценка |
|------------|--------|
| R9 (Мульти-агентность) | **Вторично.** Сначала нужно решить single-agent хорошо. Мульти-агентность — это optimization, не core. |
| R3 (Практичный набор режимов) | **Важно, но опасно.** Легко overengineer. Начать с 2-3 режимов. |

### Потенциальные проблемы решения

1. **Файлы = friction**
   - Нужно поддерживать .mind/ в актуальном состоянии
   - Может превратиться в "ещё одну документацию которую никто не читает"

2. **AI extraction ненадёжен**
   - Без human-in-the-loop будут ошибки
   - С human-in-the-loop — overhead

3. **Режимы — это культурный сдвиг**
   - Пользователи привыкли к "всеядному" AI
   - Ограничение полномочий может раздражать

## 4. Минимальный Viable Product

Следуя R5 (YAGNI), предлагаю начать с:

### MVP v0.1

1. **Один файл `.mind/context.md`** (не YAML, проще)
   - Текущий фокус
   - Активные вопросы
   - Недавние решения

2. **Два режима: `think` и `do`**
   - `think` — исследует, обсуждает, планирует
   - `do` — выполняет конкретную задачу

3. **Ручной extraction**
   - В конце сессии: "Что важного сохранить?"
   - Человек копирует в context.md

4. **Интеграция через system prompt**
   - Читаем context.md, инжектим в промпт
   - Работает с любым AI

**Это покрывает:**
- R1 (эволюционируемость) — частично
- R2 (явные режимы) — базово
- R4 (инкрементальность) — да
- R6 (фокус на диалоге) — think mode

**Это откладывает:**
- R9 (мульти-агентность)
- Автоматический extraction
- Сложную структуру .mind/

## Резюме

**Ключевая идея:** Отделить эфемерное (чат) от персистентного (знания) через файлы в репозитории.

**Основные компоненты:**
1. `.mind/` директория — project memory
2. Режимы работы — явные границы полномочий
3. Thread management — параллельные темы
4. Extraction pipeline — сохранение ценного

**Начать с:** context.md + два режима + ручной extraction.

**Главный риск:** Overhead превысит пользу. Нужно валидировать на реальном использовании.
