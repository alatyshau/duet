# Platform Instructions

This package supplies the shared Duet session prompt. These are product sources, not user configuration. Edit them here; deployed copies carry an `AUTO-GENERATED by Duet` banner and are regenerated by Duet.

## Contents

- `duet-core.md`: orientation, businesses and work, Duet tools, alpha paths, memory policy, and writing rules.

## Usage

`duet-core` is the public default and works without the private `duet-work` repository. An experimental work session adds the explicitly invoked `duet-work` skill on top of that same foundation. A business using the default core omits `system_prompt` from its manifest; Backend withdraws any previous generated business-level override on the next instruction deployment, leaving Host's global style in place.

## Delivery

Backend's `instructions.py` builds `DuetData/duet.md` from `duet-core.md`. Host deploys that single platform prompt to supported AI clients; Claude Code uses the `duet-core` output style. Backend separately deploys skills and optional system-prompt overrides from `context.json`. Business rules and knowledge stay in `INDEX.md` and its linked files; `orientation` tells the agent to read them. There are no business-level instruction templates or generated `CLAUDE.md`, `AGENTS.md`, or `gemini.md` files.

Production packaging and DEV deployment copy the Markdown sources next to Backend, excluding this README. There is no agent registry, core insertion marker, or role-specific prompt generation.

Executor and Vizir instructions have moved to the explicit-only `duet-executor` and `duet-vizir` skills in `duet-work`. They are not part of the public platform bundle, and using Duet does not require that repository.
