## Spec-driven Development

### Принцип

> **Кодовая база всегда в целостности.**
> После каждого коммита: код + spec = полная правда.
> Топик-файл может исчезнуть — и ничего не потеряется.

### Структура spec/

```
packages/<component>/spec/
├── DOMAIN.md        ← тезаурус (EN + RU ключи), иерархия
├── DATA_MODEL.md    ← схемы, форматы, constraints
├── ARCHITECTURE.md  ← структура кода, разделение слоёв
└── UI.md            ← состояния, flows, edge cases
```

### Правила для AI

**Приоритет источников:**
```
Для DONE шагов:     spec/ > топик-файл
Для TODO шагов:     топик-файл > spec/
При конфликте:      спроси человека
```

**Что читать когда:**
```
Понять текущее состояние    → читай spec/
Выполнить шаг               → читай топик (ВЫХОДЫ + шаг) + spec/
Проверить реализацию        → сравни код с spec/
```

**При изменении решения в процессе:**
```
1. Обновить spec/ (source of truth)
2. Добавить заметку в НАРРАТИВ топика
3. НЕ обязательно править ВЫХОДЫ топика (он временный)
```

### Пересечение spec ↔ топик-файл

- **Нормально и ожидаемо** в процессе проекта
- Топик = "куда идём" (может содержать нереализованное)
- Spec = "где сейчас" (только реализованное)
- После каждого коммита пересечение сокращается
- В конце проекта: весь ВЫХОДЫ ⊆ spec/

### Аналогия

```
spec/     = База данных + индексы (source of truth)
docs/     = Materialized view (refresh on demand)
Чат       = Ad-hoc query (real-time)
```

## Координация

### Иерархия процессов

```
Продукт (workspace)
└── Проект (проектная папка)
    └── Топик (топик-файл с планом)
        └── Шаг (CurrentStepWork.md)
            └── Коммит
```

### Flow работы

```
1. Сократ + Дедал-1: обсуждение, планирование
   → Топик-файл (НАРРАТИВ, ВЫХОДЫ, ПЛАН)

2. Дедал-1: детализация шага
   → CurrentStepWork.md (чеклист, контекст, задание)

3. Гефест: реализация
   → Код, тесты

4. Дедал-2 (опционально): ревью
   → Замечания в CurrentStepWork.md

5. Гефест: исправления по ревью

6. Гефест/Keeper: обновление spec/
   → spec/ актуальна

7. Коммит
   → CurrentStepWork.md очищается

8. Повторить для следующего шага
```

### Передача контекста между агентами

**Гефест получает:**
- Топик-файл (весь, для понимания контекста)
- CurrentStepWork.md (конкретное задание)
- spec/ (baseline)

**Дедал-ревьювер получает:**
- CurrentStepWork.md (что сделано)
- Код (результат)
- spec/ (эталон)

**Сократ получает:**
- Чат (история)
- Топик-файлы (состояние проектов)
- Вопросы от других агентов

## Разделение ответственности

### Человек (Субъектность)

- Принятие решений
- Взятие рисков
- Контроль и доверие (точечный доступ к файлам)
- Получение информации через чат (не лазит по папкам)

### AI (Интеллектуальная работа)

- Анализ и синтез
- Чтение файлов, навигация по структуре
- Генерация кода и документации
- Предоставление картины для принятия решений

---

## Правила для агентов

### Общие

1. **spec/ = source of truth** для текущего состояния
2. **Обновляй spec/ перед коммитом** — не после, не "потом"
3. **Топик-файл временный** — не полагайся на него для долгосрочной правды
4. **docs/ обновляется on demand** — не блокирует основную работу

### Для Гефеста (EXECUTE)

1. Перед началом шага: прочитай spec/ + CurrentStepWork.md
2. После завершения: обнови spec/ (всю, не только "затронутую часть")
3. Если решение изменилось: сначала spec/, потом код
4. Коммит = код + spec в целостности

### Для Дедала (PLANNING/REVIEW)

1. Планирование: опирайся на spec/ как baseline
2. Ревью: сравнивай результат с spec/, не с топик-файлом
3. При расхождении spec ↔ топик: spec/ главнее (для DONE)

### Для Сократа (DIALOGUE)

1. При вопросах о системе: читай spec/, отвечай человеку
2. При обсуждении изменений: фиксируй в топик-файле
3. Человек не должен лазить по папкам — дай ему синтез
