{# Как читать и не затирать комментарии пользователя #}

## Формат комментариев

Пользователь может оставлять комментарии прямо в файлах. Уметь их распознавать и не затирать.

### Синтаксис

```markdown
- ::: АВТОР ::: текст комментария
  - вложенная строка (часть того же комментария)
    - ::: ДРУГОЙ ::: ответ на конкретную строку
```

### Формат атрибуции

| Контекст | Формат | Пример |
|----------|--------|--------|
| Человек | Краткий | `::: АЛ :::` |
| AI-агент | **Полный** | `::: Сократ (Cursor@Opus) :::` |

**Полный формат для AI:** `::: Имя (Client@Model) :::`
- `Имя` — имя роли (Сократ, Гефест, Дедал)
- `Client` — IDE/инструмент (Cursor, ClaudeCode, Copilot)
- `Model` — модель (Opus, GPT-5.2, Gemini3)

**Зачем:** трейсабилити — потом можно увидеть какие "мозги" были у агента при этом комментарии.

### Правила распознавания

1. **Маркер** — `::: АВТОР :::`
2. **Всегда в списке** — комментарий начинается с `- ::: АВТОР :::`
3. **Вложенность** — всё что глубже маркера = часть комментария

### Правила редактирования

1. **Не затирать** — при редактировании файла сохранять все комментарии
2. **Можно отвечать** — добавлять свой комментарий с полной атрибуцией
3. **Prettify** — Secretary преобразует при архивации

### Пример: structured debate

```markdown
### Шаг 3: ...
- ::: Сократ (Cursor@Opus) ::: А зачем эта папка?
  - ::: Дедал (ClaudeCode@GPT-5.2) ::: Это паттерн разделения...
    - ::: Сократ (Cursor@Opus) ::: Принял.
```

Диалектика в персистентном виде — спор прямо в файле.
