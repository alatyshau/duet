# Skill: Scriptor

Полный интерактивный пайплайн транскрипции аудио/видео.

**Trigger:** `транскрибируй`, `scriptor`, `конвертни запись`

---

## Обзор

Агент ведёт пользователя через весь процесс — от медиафайла до финального протокола. Gemini слушает аудио и пишет черновой протокол (платная операция). Всю пост-обработку делает агент (бесплатно).

Пользователь вмешивается в двух точках: аудит терминов и идентификация участников.

## Константы

```
SCRIPTOR_ROOT = <определить через orientation: найти context "Scriptor" в chain (контекст с git_url) → его main_folder>
GLOSSARIES_DIR = SCRIPTOR_ROOT/glossaries
PROMPTS_DIR = SCRIPTOR_ROOT/prompts
GEMINI_PROMPTS_DIR = SCRIPTOR_ROOT/src/scriptor/prompts
TRANSCRIBE_GEMINI = SCRIPTOR_ROOT/src/scriptor/transcribe_chunk.py
TRANSCRIBE_OPENAI = SCRIPTOR_ROOT/src/scriptor/transcribe_openai.py
PYTHON = SCRIPTOR_ROOT/.venv/bin/python           # venv с google-genai, openai
MEDIA_DIR = <директория входного медиафайла>
OUTPUT_DIR = MEDIA_DIR/{name}                      # результат рядом с исходным файлом
```

## Поддерживаемые модели

| Провайдер | Модель | Скрипт | Режим | Промпт |
|-----------|--------|--------|-------|--------|
| Gemini | `gemini-2.5-pro` (по умолчанию) | `TRANSCRIBE_GEMINI` | LLM с аудио | полный промпт + глоссарий |
| Gemini | `gemini-2.5-flash` | `TRANSCRIBE_GEMINI` | LLM с аудио | полный промпт + глоссарий |
| OpenAI | `gpt-4o-audio-preview` | `TRANSCRIBE_OPENAI` | Chat Completions с аудио | полный промпт + глоссарий |
| OpenAI | `gpt-4o-transcribe` | `TRANSCRIBE_OPENAI` | Transcription API (ASR) | глоссарий как хинт (без промпт-файла) |

Спросить пользователя какую модель использовать. API-ключи хранятся в `SCRIPTOR_ROOT/.env`:
- `GEMINI_API_KEY` — для Gemini моделей
- `OPENAI_API_KEY` — для OpenAI моделей

## Процедура

### Шаг 0: Инициализация

1. Спросить пользователя:
   - **Путь к медиафайлу** (если не указан в сообщении)
   - **Какой глоссарий?** — показать список файлов в `GLOSSARIES_DIR` и **обязательно спросить пользователя**. Агент НИКОГДА не выбирает глоссарий автоматически, даже если рядом есть уже обработанные файлы с известным глоссарием. Можно указать несколько — тогда объединить содержимое.
   - **Какая модель?** — по умолчанию `gemini-2.5-pro`. См. таблицу «Поддерживаемые модели».
2. Определить `{name}` из имени медиафайла (без расширения, транслитерация не нужна).
3. `OUTPUT_DIR` = директория медиафайла / `{name}/`. Создать эту папку.
4. Проверить:
   - `ffmpeg` и `ffprobe` в PATH
   - `SCRIPTOR_ROOT/.env` содержит нужный API-ключ:
     - Для Gemini моделей: `GEMINI_API_KEY` (не пустой)
     - Для OpenAI моделей: `OPENAI_API_KEY` (не пустой)
   - `SCRIPTOR_ROOT/.venv/` существует (если нет — `python3 -m venv .venv && .venv/bin/pip install google-genai openai`)

### Шаг 1: Конвертация в mp3

```bash
ffmpeg -i "{input}" -vn -ac 1 -ar 16000 -ab 128k "{OUTPUT_DIR}/audio.mp3"
```

- Если входной файл уже mp3 mono 16kHz — пропустить.
- Показать пользователю длительность файла через `ffprobe`.
- **Кэширование:** если `audio.mp3` уже существует — пропустить, сообщить пользователю.

### Шаг 2: Нарезка на чанки

Параметры: `chunk_duration=20мин`, `overlap=30сек`.

Для файла длительностью D минут:
```
chunk_000: 00:00 — 20:00
chunk_001: 19:30 — 39:30
chunk_002: 39:00 — 59:00
...
```

Команда для каждого чанка:
```bash
ffmpeg -i "{audio.mp3}" -ss {start} -to {end} -c copy "{OUTPUT_DIR}/chunks/chunk_{NNN}.mp3"
```

- Если длительность ≤ 20 минут — один чанк, нарезка не нужна, просто скопировать audio.mp3 как chunk_000.mp3.
- **Кэширование:** если папка `chunks/` уже содержит файлы — пропустить, сообщить пользователю.

### Шаг 3: Протоколирование чанков через Gemini 💰

Это единственный платный шаг. Минимизировать количество вызовов.

Команда зависит от выбранной модели:

**Gemini** (`gemini-2.5-pro`, `gemini-2.5-flash`):
```bash
"{PYTHON}" "{TRANSCRIBE_GEMINI}" \
    "{chunk_path}" \
    "{OUTPUT_DIR}/raw/chunk_{NNN}.md" \
    --prompt "{GEMINI_PROMPTS_DIR}/transcribe.md" \
    --glossary "{glossary_path}" \
    --offset "{HH:MM:SS}" \
    --model "{model}"
```

**OpenAI chat** (`gpt-4o-audio-preview`):
```bash
"{PYTHON}" "{TRANSCRIBE_OPENAI}" \
    "{chunk_path}" \
    "{OUTPUT_DIR}/raw/chunk_{NNN}.md" \
    --prompt "{GEMINI_PROMPTS_DIR}/transcribe.md" \
    --glossary "{glossary_path}" \
    --offset "{HH:MM:SS}" \
    --model "gpt-4o-audio-preview"
```

**OpenAI transcribe** (`gpt-4o-transcribe`):
```bash
"{PYTHON}" "{TRANSCRIBE_OPENAI}" \
    "{chunk_path}" \
    "{OUTPUT_DIR}/raw/chunk_{NNN}.md" \
    --glossary "{glossary_path}" \
    --model "gpt-4o-transcribe"
```
Примечание: `--prompt` и `--offset` не используются — это ASR-модель, формат вывода определяется скриптом.

Где `offset` — абсолютное время начала чанка от начала записи (с учётом перекрытия).

- **Кэширование:** если `raw/chunk_{NNN}.md` уже существует — пропустить этот чанк.
- Между вызовами пауза 2 секунды (rate limiting).
- Показывать прогресс: `Чанк 3/7...`

### Шаг 4: Склейка чанков

Если чанк один — просто скопировать `raw/chunk_000.md` как `merged.md`.

Если чанков несколько — агент читает промпт `GEMINI_PROMPTS_DIR/merge_chunks.md` и склеивает последовательно:
1. **Выровнять спикеров.** Gemini в каждом чанке назначает спикерам свои буквы (A, B, C...) независимо. Между чанками одни и те же люди могут получить разные буквы. Перед склейкой нужно:
   - Прочитать зону перекрытия (хвост чанка N и голову чанка N+1).
   - Сопоставить реплики по содержанию — найти, какие буквы в чанке N+1 соответствуют каким буквам в чанке N.
   - Переименовать спикеров в чанке N+1 (и всех последующих) по маппингу, чтобы буквы были консистентны по всему протоколу.
   - Если в новом чанке появляются спикеры, которых не было раньше — назначить им следующие свободные буквы.
2. Прочитать хвост чанка N (последние ~2 минуты по таймкодам) и голову чанка N+1 (первые ~2 минуты).
3. По правилам из промпта: найти зону перекрытия, удалить дубликаты, сшить.
4. Записать результат в `OUTPUT_DIR/merged.md`.

- **Кэширование:** если `merged.md` уже существует — пропустить, сообщить пользователю.

### Шаг 5: Тематическая сегментация

Агент читает промпт `PROMPTS_DIR/segment.md` и применяет к `merged.md`:
- Разбивает протокол на тематические разделы с заголовками `##`.
- НЕ меняет текст реплик, таймкоды, разбивку на абзацы.
- Записывает результат в `OUTPUT_DIR/segmented.md`.

### Шаг 6: Аудит терминов ⏸️

Агент читает промпт `PROMPTS_DIR/audit_terms.md` и применяет к `segmented.md`:
- Собирает все `[?слово]` маркеры, оставленные Gemini.
- Ищет потенциально неправильно распознанные термины, имена, аббревиатуры.
- Формирует таблицу находок.
- Записывает в `OUTPUT_DIR/audit.md`.

**СТОП. Показать пользователю результат аудита и спросить:**

> Вот список подозрительных терминов. Посмотри и скажи:
> 1. Какие исправить? (например: "изобретании" → "Изобретальне")
> 2. Какие новые термины добавить в глоссарий?
> 3. Или всё ок — продолжаем?

**После ответа пользователя:**
- Выполнить find & replace в `segmented.md` для каждого исправления.
- Добавить новые термины в выбранный глоссарий (в конец файла, в том же формате).

### Шаг 7: Участники и роли ⏸️

Агент анализирует протокол и извлекает:
- Имена, упомянутые в тексте (кого называют по имени).
- Роли (кто что предлагал, кто вёл, кто за что отвечает).

**Показать пользователю и спросить:**

> Вот кого я нашёл в протоколе:
> - Оля — озвучивает задачи, ответственна за идентификацию сообщества
> - Андрей — ведёт повестку, рассказывает про S3
> - Алексей — координирует логистику
> - ...
>
> Кого я пропустил? Кто ещё участвовал?

**После ответа пользователя:**
- Записать список участников в `OUTPUT_DIR/participants.md`.

### Шаг 8: Финальная сборка

Объединить в один файл `OUTPUT_DIR/transcript.md`:

```markdown
# {name}

Дата: {YYYY-MM-DD}
Глоссарий: {имя глоссария}
Длительность: {HH:MM:SS}

> ⚠️ Разделение на реплики приблизительное. Тире (—) означает смену говорящего, но не идентифицирует кто именно говорит.

## Участники

{содержимое participants.md}

---

{содержимое segmented.md}
```

Сообщить пользователю:

> Готово! Финальный протокол: `{name}/transcript.md`
> Глоссарий обновлён: {N} новых терминов добавлено.

---

## Кэширование

Каждый шаг проверяет наличие выходных файлов. При повторном запуске пайплайн продолжает с того места, где остановился. Для полного перезапуска пользователь может сказать «начни заново» — тогда очистить `OUTPUT_DIR/` и начать с шага 1.

## Обработка ошибок

- **ffmpeg не найден** → сообщить пользователю, предложить `brew install ffmpeg`
- **GEMINI_API_KEY не задан** → сообщить: «Впиши ключ в Scriptor/.env. Получить: https://aistudio.google.com/apikey»
- **OPENAI_API_KEY не задан** → сообщить: «Впиши ключ в Scriptor/.env. Получить: https://platform.openai.com → API keys. Нужно пополнить баланс (от $5).»
- **Gemini/OpenAI API ошибка** → повторить до 3 раз с паузой 5/10/20 секунд
- **Файл слишком большой для Gemini** → уменьшить chunk_duration и перенарезать
