## О проекте Duet

**Duet** — система управления знаниями и делами, построенная на принципах:

1. **Data Sovereignty** — данные хранятся в Google Drive в вечных форматах (MD, CSV, PY)
2. **Deep LLM Integration** — интеграция с LLM через MCP (Model Context Protocol)
3. **GPD-онтология** — иерархия Предприятие → Дело → Продукт

### Структура монорепо

```
Duet/
├── apps/
│   ├── host/                 ← Electron приложение (Menu Bar daemon)
│   ├── vscode/               ← VS Code расширение
│   └── ai-instructions/      ← Продукт: AI-протоколы (не инструкции для тебя!)
├── packages/
│   ├── core/                 ← Общая логика (парсеры, типы)
│   └── mcp-server/           ← MCP сервер для LLM
└── docs/                     ← Документация
```

## Правило: FILE_DOCUMENTATION

Каждый файл в проекте ОБЯЗАН содержать документирующую шапку.

### Цель

Документация должна быть такого качества, что **полный новичок** в технологии:
1. Понимает зачем файл существует
2. Понимает каждое нетривиальное поле/секцию
3. Знает куда идти за подробностями

Если после прочтения остаются вопросы — документация плохая.

### Формат шапки

```
ЧТО: Краткое описание (1 строка)
ЗАЧЕМ: Причина существования
КТО ИСПОЛЬЗУЕТ: Какие процессы/инструменты читают этот файл
```

Далее — секции с объяснением каждого поля/блока.

### Где размещать

**Файлы с комментариями** — шапка прямо в файле:
- `.ts`, `.js`, `.tsx` → `/* ... */`
- `.yaml`, `.yml` → `# ...`
- `.md` → Первый заголовок + описание
- `.py` → `""" ... """`

**Файлы без комментариев** — файл-компаньон рядом:
- `package.json` → `package.json.md`
- `tsconfig.json` → `tsconfig.json.md`
