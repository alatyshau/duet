# CLAUDE.md — Инструкции для ИИ-ассистентов

## Правило: FILE_DOCUMENTATION

Каждый файл в проекте ОБЯЗАН содержать документирующую шапку.

### Цель документации

Документация должна быть такого качества, что **полный новичок** в технологии:
1. Понимает зачем файл существует
2. Понимает каждое нетривиальное поле/секцию
3. Знает куда идти за подробностями

Если после прочтения остаются вопросы — документация плохая.

### Как достичь

Для каждого нетривиального элемента:
- **Либо** объясни прямо здесь (если объяснение короткое)
- **Либо** дай ссылку на документацию (если тема большая)
- **Либо** напиши "см. `другой-файл.md`" (если объяснено в проекте)


### Формат шапки
```
ЧТО: Краткое описание (1 строка)
ЗАЧЕМ: Причина существования
КТО ИСПОЛЬЗУЕТ: Какие процессы/инструменты читают этот файл
```

Далее — секции с объяснением каждого поля/блока.


### Для файлов с поддержкой комментариев

Добавляем шапку прямо в файл:
- `.ts`, `.js`, `.tsx` → `/* ... */` или `// ...`
- `.yaml`, `.yml` → `# ...`
- `.md` → Первый заголовок + описание
- `.py` → `""" ... """`


### Для файлов БЕЗ поддержки комментариев

Создаём файл-компаньон рядом:
- `package.json` → `package.json.md`
- `tsconfig.json` → `tsconfig.json.md`
- Любой `.json` → `.json.md` рядом

### Пример плохой документации
```markdown
# config.json
Конфигурация проекта.
```

Плохо: не объясняет поля, новичок не поймёт.

### Пример хорошей документации
```markdown
# config.json

ЧТО: Конфигурация Duet Host.
ЗАЧЕМ: Хранит пользовательские настройки между сессиями.
КТО ИСПОЛЬЗУЕТ: Electron main process при старте.

## Поля

### roots
Массив корневых папок, которыми управляет Duet.
Duet сканирует их на наличие node_modules для миграции.

### derived.patterns
Список папок, которые выносятся в ~/.duet-local/.
Подробнее о механизме: см. docs/derived-folders.md
```
