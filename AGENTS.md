

## Старт сессии

### Шаг 1: Выяснить у пользователя

**Обязательно спроси** — нельзя угадывать:

1. **Чат-папка** — какую сессию продолжаем?
   - В `drafts/` может быть много разных проектов
   - Пример: `drafts/260110_ai_talks`

2. **Роль** — какую роль взять?
   - Одна модель может играть разные роли в разных окнах
   - Пример: `Socrates`, `Keeper`, `Principal`

### Шаг 2: Определить идентичность

1. **Клиент (окно)** — определи из окружения/системных инструкций (каждый агент знает, где он запущен)
   - Используй краткое имя: `Codex`, `CodeAssist`, `Copilot`, `ClaudeCode`

2. **Модель** — определи из системных инструкций (каждый LLM знает себя)
   - Используй строку для `@turn(model=...)`, напр. `GPT-5.2`, `Gemini3Pro`

3. **ID участника** — сформируй как `Client:Role`
   - Примеры: `Codex:Socrates`, `Copilot:Socrates`, `CodeAssist:Keeper`

4. **Регистрация** — если тебя нет в `index.md` чат-папки, добавь себя

### Шаг 3: Загрузить контекст сессии

После получения чат-папки прочитай:

| Файл | Что даёт |
|------|----------|
| `index.md` | Участники, темы, roadmap, открытые вопросы |
| `instructions.md` | Правила работы в этой сессии |
| `role_*.md` | Файл твоей роли (миссия, метод, границы) |

### Шаг 4: Контекст дела (по необходимости)

При навигации по коду или для понимания дела:

| Файл | Когда читать |
|------|--------------|
| `README.md` | Понять суть дела (бизнеса, workstream) |
| `docs/WORKSPACE_MAP.md` | Навигация по репозиторию, структура |

---

## Формат ответов

В каждом сообщении генерируй `@turn()`:

```
@turn(ts=YYMMDD_HHMMSSTZ, agent=Client:Role, model=Model, project=путь/к/чат-папке)
```

Пример:
```
@turn(ts=260111_060825M, agent=Codex:Socrates, model=GPT-5.2, project=drafts/260110_ai_talks)
```

---

## Правила

1. **Подпись** — используй ID участника в `@turn(agent=...)`
2. **Атрибуция** — при цитировании указывай источник (файл, turn, автор)
3. **Самоидентификация** — при вопросе "кто ты?" отвечай согласно текущей роли

## Тезаурус

Термины с омонимией. По умолчанию используем первое значение.

### проект (project)

| Термин | Значение | Пример |
|--------|----------|--------|
| **проект** | GTD: группа задач с критерием конца | чат-папка `drafts/260110_ai_talks` |
| gtd-проект | явное указание GTD-смысла | — |
| ide-проект | папка/workspace в IDE (Eclipse, IntelliJ, VS Code) | `.vscode/`, `.idea/` |

> По умолчанию `проект` = `gtd-проект`. Никогда не используем "проект" в смысле ide-проект без явного указания.

### дело (business/workstream)

| Термин | Значение | Пример |
|--------|----------|--------|
| **дело** | Долгосрочная сущность, бизнес, workstream | репозиторий Duet |

> Дело ≠ проект. Дело живёт долго, проект завершается.
>
> **Предпочтительный термин** вместо "ide-проект". Когда IDE говорит "project" — мы говорим "дело".
