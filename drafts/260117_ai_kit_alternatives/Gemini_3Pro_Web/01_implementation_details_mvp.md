Здесь мы создаем файловую структуру, которая обеспечивает **R1 (Эволюционируемость)** и **R9 (Мульти-агентность)**, так как файлы хранятся в Git вместе с проектом.

---

## 1. Структура директории `.ai`

Создайте в корне вашего проекта папку `.ai/`. Она станет «внешним гиппокампом» для любого AI, с которым вы работаете.

```text
/project-root
  ├── .ai/
  │   ├── context.md          # Глобальная память проекта (Long-term memory)
  │   ├── active_task.md      # Текущий фокус и статус (Short-term memory)
  │   ├── decisions.md        # Журнал принятых решений (Immutable history)
  │   └── modes/              # Системные промпты (Persona definitions)
  │       ├── 00_meta_instruction.md # Базовая инструкция о том, как читать эти файлы
  │       ├── 01_clarify.md
  │       ├── 02_architect.md
  │       ├── 03_execute.md
  │       └── 04_synthesize.md
  ├── src/
  └── ...

```

## 2. Файлы состояния (State Files)

Эти файлы вы будете «скармливать» AI в начале сессии (например, через `@Folder` в Cursor или контекст в ChatGPT).

### `.ai/context.md` (Глобальный контекст)

Этот файл меняется редко, но содержит суть проекта.

```markdown
# Project Context

## Vision
Краткое описание того, что мы строим и зачем. Какую проблему решаем?

## Core Constraints & Principles
- Tech Stack: [Язык, Фреймворки, Версии]
- Architecture: [Clean Arch, Microservices, Monolith...]
- Code Style: [Ссылка на линтер или краткие правила]
- Principles: [YAGNI, SOLID, Functional core / Imperative shell]

## Domain Dictionary
- **Term A**: Определение...
- **Term B**: Определение...

## Key Components
1. Component A - ответственность...
2. Component B - ответственность...

```

### `.ai/active_task.md` (Оперативная память)

Этот файл меняется каждый день/час. Он решает проблему **R6 (Фокус)**.

```markdown
# Active Task Status

## Current Goal
Четкое описание того, над чем мы работаем ПРЯМО СЕЙЧАС.

## Context for this task
Специфические детали, сниппеты ошибок или требования, актуальные только сейчас.

## Progress Log
- [x] Шаг 1: Проанализировано...
- [ ] Шаг 2: Нужно реализовать X
- [ ] Шаг 3: Тестирование

## Scratchpad (Черновик)
Место для временных мыслей AI и пользователя, чтобы не засорять чат.

```

### `.ai/decisions.md` (Лог решений)

Решает проблему **R1** и **R4**, позволяя не возвращаться к обсужденному.

```markdown
# Architecture Decision Records (ADR) - Light

## [YYYY-MM-DD] 001. Выбор базы данных
**Decision:** PostgreSQL
**Reasoning:** Нам нужна надежность транзакций и JSONB поля. NoSQL отклонили из-за сложности связей.

## [YYYY-MM-DD] 002. Структура модулей
**Decision:** Feature-based slicing
**Reasoning:** Чтобы избежать гигантских папок controllers/ и models/.

```

## 3. Файлы режимов (Mode Definitions)

Эти файлы — это **инструкции для AI**, как себя вести. При начале диалога вы пишете:

> *"Прочитай `.ai/context.md` и действуй в режиме `.ai/modes/01_clarify.md`"*

### `modes/01_clarify.md` (Режим Сократа)

*Цель:* Понять задачу до написания кода. **R6 (Взаимопонимание).**

```markdown
# MODE: CLARIFY

## ROLE
Ты — Senior Business Analyst и QA Engineer. Ты дотошный, скептичный и внимательный к деталям.

## OBJECTIVE
Твоя цель — ПОЛНОСТЬЮ понять задачу в `active_task.md` и выявить пропущенные требования или логические нестыковки в `context.md`.

## CONSTRAINTS (CRITICAL)
1. **NO CODE:** Тебе ЗАПРЕЩЕНО писать код решения.
2. **NO SOLUTIONS:** Не предлагай, как это сделать. Только спрашивай "Что" и "Зачем".
3. **ASK QUESTIONS:** Задавай по 1-3 вопроса за раз. Жди ответа.
4. **UPDATE:** В конце предложи обновленную версию текста для `active_task.md` с учетом выясненных деталей.

## STYLE
Прямой, без лишней вежливости. Ищи граничные случаи (edge cases).

```

### `modes/02_architect.md` (Режим Планировщика)

*Цель:* Декомпозиция. **R4 (Инкрементальность).**

```markdown
# MODE: ARCHITECT

## ROLE
Ты — System Architect. Ты ценишь простоту (KISS) и поддерживаемость.

## OBJECTIVE
Создать пошаговый план реализации текущей цели из `active_task.md`.

## CONSTRAINTS
1. Не пиши финальный код. Только псевдокод или сигнатуры интерфейсов.
2. Ссылайся на `decisions.md`, чтобы не нарушать прошлые договоренности.
3. Разбей задачу на атомарные шаги.
4. Предложи, какие файлы нужно создать или изменить.

## OUTPUT FORMAT
Обнови секцию "Progress Log" в файле `active_task.md`.

```

### `modes/03_execute.md` (Режим Кодера)

*Цель:* Написание кода.

```markdown
# MODE: EXECUTE

## ROLE
Ты — Senior Developer. Ты пишешь чистый, типизированный и безопасный код.

## OBJECTIVE
Реализовать ОДИН пункт из плана в `active_task.md`.

## CONSTRAINTS
1. Строго следуй `context.md` (стиль кода, технологии).
2. Не импровизируй в архитектуре. Если план плох — СТОП и вернись в режим Architect.
3. Не удаляй существующий код без объяснения.
4. Добавляй комментарии к сложному коду.

## STYLE
Минимум болтовни. Только код и краткие пояснения.

```

### `modes/04_synthesize.md` (Режим Сжатия)

*Цель:* Сохранить знания перед очисткой чата. **R1 (Эволюция).**

```markdown
# MODE: SYNTHESIZE

## ROLE
Ты — Технический писатель и хранитель знаний.

## OBJECTIVE
Проанализируй текущую сессию чата и обнови файлы в папке `.ai/`.

## ACTIONS
1. **Context Update:** Если мы узнали что-то новое о проекте, предложи diff для `context.md`.
2. **Decision Log:** Если мы приняли важное решение, сформулируй новую запись для `decisions.md`.
3. **Task Status:** Обнови `active_task.md`: отметь выполненное, удали неактуальное, перенеси важное из "Scratchpad" в документацию.
4. **Cleanup:** Предложи, что можно удалить, чтобы следующая сессия началась с чистого листа.

```
