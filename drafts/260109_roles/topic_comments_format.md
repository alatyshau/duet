# Формат комментариев в документах

**Статус:** Черновик

---

## МОТИВАЦИЯ

### Зачем нужен формат комментариев

В ходе работы над документами возникает потребность комментировать — задавать вопросы, делать замечания, вести диалог прямо внутри текста. Нужен единый синтаксис который:
- Отличает комментарий от основного текста
- Показывает автора (АЛ, ИИ, конкретная роль)
- Поддерживает вложенность (ответ на ответ)
- Легко читается и пишется

## СИНТАКСИС

### Базовый формат

Комментарии используют вложенные списки с маркером автора:

```markdown
- ::: АЛ ::: мой коммент (начинается тред)
  - это вложенная строчка моего коммента
    - ::: ИИ ::: ответ ИИ к этой строчке
```

### Правила

1. **Всегда часть списка** — комментарий начинается с `- ::: АВТОР :::`
2. **Может быть многострочным** — вложенные строки без нового маркера продолжают тот же комментарий
3. **Маркер автора** — `::: АЛ :::` или `::: ИИ :::` (или другой идентификатор)

---

## ГРАНИЦЫ КОММЕНТАРИЯ

Комментарий = маркер + всё что вложено **глубже** (пока не встретится новый маркер или выход на тот же/меньший уровень).

```markdown
- ::: AL ::: comment 052          ← комментарий 052
    - строчка 1 — часть 052       ← ЧАСТЬ 052 (глубже)
    - строчка 2 — часть 052       ← ЧАСТЬ 052 (глубже)
- эта строка уже документ         ← документ (тот же уровень, нет маркера)
```

---

## ВЛОЖЕННОСТЬ

### Комментарий должен быть К ЧЕМУ-ТО

**Нельзя:** комментарий сразу вложен в другой комментарий
```markdown
- ::: АЛ ::: комм
  - ::: ИИ ::: ответ   ← НЕПРАВИЛЬНО (к чему ответ?)
```

**Можно:** комментарии на одном уровне (диалог)
```markdown
- ::: АЛ ::: комм
- ::: ИИ ::: ответ     ← ПРАВИЛЬНО (ответ к комму выше)
```

**Можно:** ответ к конкретной строке внутри комментария
```markdown
- ::: АЛ ::: комм
  - эта строчка
    - ::: ИИ ::: ответ к этой строчке  ← ПРАВИЛЬНО
```

## КОНТЕКСТНОЕ РАЗМЕЩЕНИЕ

| Контекст | Как делать |
|----------|------------|
| К элементу списка | Под-пунктом (вложить) |
| К параграфу | Пунктом 1-го уровня |

```markdown
- текст документа
  - ::: АЛ ::: комментарий к пункту

текст параграфа
- ::: АЛ ::: комментарий к параграфу
```

## PRETTIFY (задача Secretary)

Когда Secretary встречает сырой формат `::: АЛ :::`, он преобразует в читаемый:

| Сырой формат | После prettify |
|--------------|----------------|
| `::: АЛ :::` | **АЛ \| 2025-01-09 17:00** |
| `::: ИИ :::` | **ИИ \| 2025-01-09 17:00** |

С тегом:
| Сырой формат | После prettify |
|--------------|----------------|
| `::: АЛ ::: Q001` | **АЛ \| Q001 \| 2025-01-09 17:00** |

## ТЕГИ И СЧЁТЧИК

Теги вида `Q001`, `Q002` нумеруются последовательно в рамках файла.

## ПРИМЕР

**До prettify:**
```markdown
- ::: АЛ ::: Здесь непонятна логика выбора
  - почему именно два окна, а не три?
    - ::: ИИ ::: Когнитивная нагрузка — три параллельных контекста сложнее удерживать
```

**После prettify:**
```markdown
- **АЛ | 2025-01-09 17:00** Здесь непонятна логика выбора
  - почему именно два окна, а не три?
    - **ИИ | 2025-01-09 17:05** Когнитивная нагрузка — три параллельных контекста сложнее удерживать
```

## ВЫХОДЫ

**Спецификация формата комментариев:**

| Элемент | Синтаксис | Пример |
|---------|-----------|--------|
| Маркер | `::: АВТОР :::` | `::: АЛ :::`, `::: ИИ :::` |
| С тегом | `::: АВТОР ::: TAG` | `::: АЛ ::: Q001` |
| Prettified | `**АВТОР \| DATE**` | `**АЛ \| 2025-01-09 17:00**` |

**Правила:**
1. Комментарий всегда часть списка (`- ::: АВТОР :::`)
2. Вложенность = продолжение комментария (пока нет нового маркера)
3. Комментарий к комментарию → на том же уровне или к конкретной строке
4. Secretary делает prettify при обработке
