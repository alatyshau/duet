# Протокол Навигационного Маяка (Navigation Beacon Protocol)

ЧТО: Спецификация обязательного HUD-заголовка в каждом ответе AI для привязки контекста.
ЗАЧЕМ: Решить проблему "потери контекста" в длинных диалогах; заставить AI "вспоминать" проект/задачу перед каждым ответом.
КТО ИСПОЛЬЗУЕТ: AI-агенты при генерации ответов; Principal при проектировании UX взаимодействия.

**Статус:** Черновик. Идея частично реализована в системе ролей (каждая роль имеет свой "маяк" в виде шапки).

---

**Цель:** Обеспечить непрерывную привязку контекста (Context Anchoring) и визуальное подтверждение статуса системы в каждом сообщении.

**Проблема:** В длинных диалогах или при работе с несколькими проектами AI может "потерять" контекст (забыть, над каким проектом идет работа, или какие инструкции активны).

**Решение:** Внедрение обязательного "Навигационного Маяка" (HUD) — стандартизированного заголовка в начале каждого ответа.

---

## 1. Правило Маяка

**ЗАКОН:** Каждое сообщение AI (кроме односложных подтверждений по явной просьбе) **ОБЯЗАНО** начинаться с блока "Навигационный Маяк".

**Формат:**
Блок должен быть отделен от основного текста горизонтальной чертой.

```markdown
**Проект:** [Название] | **Корень:** `[Краткий путь]` | **BIOS:** [Версия/Ссылка]
**Контекст:** [Текущая Активная Задача] | **Дата:** YYYY-MM-DD

---

[Основной текст ответа...]
```

## 2. Элементы Маяка

1.  **Проект:** Название текущего проекта (из `README.md`). Ссылка на файл `README.md` приветствуется.
2.  **Корень:** Относительный путь к корню проекта (например, `.../ТехноЛаб/Duet`). Помогает убедиться, что мы не "улетели" в другую папку.
3.  **BIOS:** Ссылка на активный файл инструкций (например, `AI_INSTRUCTIONS.md`) и его версия. Это напоминает AI, по каким правилам он играет.
4.  **Контекст:** Название задачи из `Task_Plan.md`, над которой мы работаем *прямо сейчас*.
5.  **Дата:** Текущая дата (важно для ведения истории).

## 3. Процедура Инициализации (Handshake)

При начале новой сессии или смене проекта, Субъект подает команду инициализации:

> *"Привет, работаем над проектом [Путь/Название]. Изучи README и BIOS."*

**Действия AI:**
1.  Найти указанную папку.
2.  Прочитать `README.md` и `AI_INSTRUCTIONS.md` (BIOS).
3.  Сформировать первый Маяк.
4.  Доложить о готовности.

**Субъект:**

**AI:**

---

## 5. Философия

Маяк — это не просто текст. Это **ритм**. Это **дисциплина**.
Каждый раз, генерируя этот блок, AI вынужден "вспомнить" (retrieve) ключевые параметры сессии. Это технически повышает качество ответов, удерживая внимание модели на системных промптах.

## 6. Роль и Структура README.md

Для корректной работы Маяка и автоматического определения контекста, структура `README.md` файлов в проекте строго регламентирована.

### 6.1. Иерархия README
*   **Корневой README Проекта (Project Root):**
    *   **Обязательно:** Содержит название проекта, миссию и **ссылку на файл инструкций (BIOS)**.
    *   **Маркеры:** Фразы "Карта Проекта", "Project Map", "Root Definition".
    *   **Функция:** Служит точкой входа. Именно этот файл ищет AI, поднимаясь вверх по папкам, чтобы понять, где он находится.
*   **Вложенные README (Sub-folder / Module):**
    *   Описывают конкретную папку (модуль, компонент).
    *   **НЕ** должны содержать глобальных определений проекта, чтобы не сбивать AI с толку.

### 6.2. Ссылка на BIOS (Instructions Anchor)
Корневой `README.md` **обязан** содержать явную ссылку на файл инструкций. Это обеспечивает кросс-платформенную совместимость (работает и в IDE, и в VS Code, и в веб-чате).

**Пример заголовка Корневого README:**
```markdown
# Название Проекта

> **🤖 AI NOTICE:** This project is managed by the protocols in [AI_INSTRUCTIONS.md](./AI_INSTRUCTIONS.md). Read them first.

## Карта Проекта
...
```

### 6.3. Работа в Монорепозиториях и Сложных Воркспейсах
В структурах с глубокой вложенностью (например, `!МетаЛаб/ТехноЛаб/Duet`) могут встречаться промежуточные `README.md` (уровня домена или воркспейса), которые не являются корнем конкретного проекта.

**Алгоритм Поиска Корня (Truth-Seeking Algorithm):**
1.  AI начинает поиск от **Активного Файла** вверх по директориям.
2.  В каждой папке проверяет наличие `README.md`.
3.  **Критерий Истины:** Файл считается Корнем Проекта **ТОЛЬКО** если он содержит:
    *   Явную ссылку на `AI_INSTRUCTIONS.md` (BIOS).
    *   ИЛИ маркер "Project Root" / "Карта Проекта".
4.  **Пропуск:** Если `README.md` описывает группу проектов (например, "Описание домена ТехноЛаб") и не содержит ссылки на BIOS, AI продолжает поиск (или останавливается, если это и есть цель, но тогда работает по общим правилам, если они там указаны).
5.  **Приоритет:** Ближайший к файлу "правильный" README побеждает. Это обеспечивает локализацию контекста.

## 7. Изоляция Контекста и Обработка Шума

**ЗАКОН:** Один чат-сессия всегда привязана ровно к **одному** Главному Проекту (определенному при инициализации или первым Маяком).

### 7.1. Фильтрация Вкладок (Noise Filtering)
При формировании ответа AI анализирует список открытых файлов (вкладок), предоставленных IDE.
*   **Свой-Чужой:** Файлы, путь к которым не начинается с `PROJECT_ROOT` Главного Проекта, считаются "Шумом" (Noise).
*   **Действие:** AI **обязан** игнорировать содержимое "шумовых" файлов при решении задач Главного Проекта, если нет явного запроса на их использование.
*   **Индикация:** Если обнаружен значительный шум (файлы других проектов), AI может добавить в Маяк пометку (опционально): `Шум: игнорирую 3 файла`. Не следует перечислять имена файлов, чтобы не засорять историю контекста.

### 7.2. Кросс-проектные Ссылки (Cross-Project References)
Единственное исключение из правила изоляции — **явный запрос Субъекта**.
*   **Сценарий:** Субъект просит сравнить файл из текущего проекта с файлом из другого проекта (который открыт во вкладке).
*   **Разрешение:** В этом случае AI имеет право (и обязан) прочитать "чужой" файл.
*   **Принцип:** "Что в промпте — то и важно. Что просто открыто — фон."

**Пример:**
> *Субъект:* "Сравни `Methodology.md` (наш) с `../GPD-Method/README.md` (открыт в табе)."
> *AI:* Читает оба файла, выполняет сравнение. Контекст чата остается в `Duet`.
