## МОТИВАЦИЯ

### Зачем единая структура

> [ALA] Проанализировал твои документы. Вырисовывается такая структура для топик-документов (и для ролевых такая же — единый формат).

Единый формат даёт:
- Предсказуемость — AI и человек знают где что искать
- Восстанавливаемость — новый AI читает файл и понимает контекст
- Навигацию — можно быстро перейти к нужной секции

### Принцип гранулярности

> [ALA] Можно на каждый продукт, тему, проект, идею — самостоятельную — создавать topic. У КАЖДОГО чат-документа должна быть своя секция "План внедрения". Смысл секции в том, чтобы было ясно, когда уже можно этот чат-документ удалить.

**Один документ = одна тема/проект/идея.**

Если в ходе нарратива кристаллизуется новая самостоятельная тема — создаём новый `topic_*.md` файл.

> [ALA] Секция должна формулировать прежде всего критерии завершённости (Definition of Done). В самом начале, когда тема только возникает, план не определён — нужно честно об этом говорить.

Определены стадии развития секции:
1. **Неясно** — просто болтаем, непонятно зачем
2. **Планирование** — появились выходы, можно формулировать критерии
3. **В работе** — шаги с TODO/WIP/IN_REVIEW/DONE
4. **Готово** — все критерии выполнены, можно архивировать

## ВЫХОДЫ

### Каноническая структура чат-документа

```markdown
# Название документа

**Статус:** ...

---

## МОТИВАЦИЯ
Зачем этот документ существует. Какую проблему решает.

---

## ССЫЛКИ
Внешний контекст: ссылки на другие файлы, цитаты, references.

---

## НАРРАТИВ
История развития мысли. Диалектика. Как пришли к текущему состоянию.

---

## ВЫХОДЫ
Структурированный результат работы над темой.

---

## ПЛАН ВНЕДРЕНИЯ
Критерии завершённости. Шаги внедрения.
```

### Таблица секций

| Секция | Порядок | Описание |
|--------|---------|----------|
| МОТИВАЦИЯ | 1 | Зачем документ существует |
| ССЫЛКИ | 2 | Внешний контекст |
| НАРРАТИВ | 3 | История развития мысли (процесс) |
| ВЫХОДЫ | 4 | Структурированный результат (продукт) |
| ПЛАН ВНЕДРЕНИЯ | 5 | Критерии завершённости, шаги |

**Все секции обязательные. Количество секций H2 = 5. Строго.**

Дополнительный контент — только как подсекции (H3, H4).

### Спецификация секции ПЛАН ВНЕДРЕНИЯ

#### Назначение

**Definition of Done** — критерии завершённости. Что должно произойти, чтобы файл можно было архивировать.

#### Стадии развития

| Стадия | Статус секции | Что происходит |
|--------|---------------|----------------|
| **Неопределённость** | `неясно` | Тема только возникла. Непонятно зачем |
| **Планирование** | `планирование` | Появились выходы. Формулируем критерии |
| **Исполнение** | `в работе` | Шаги с TODO/WIP/IN_REVIEW/DONE |
| **Завершение** | `готово` | Все критерии выполнены. Можно архивировать |

#### Формат по стадиям

**Стадия "Неопределённость":**
```markdown
## ПЛАН ВНЕДРЕНИЯ

**Статус:** неясно

**Критерии завершённости:** Пока непонятно. Просто исследуем тему.
```

**Стадия "Планирование":**
```markdown
## ПЛАН ВНЕДРЕНИЯ

**Статус:** планирование

**Критерии завершённости:**
- [ ] Спецификация добавлена в базовые инструкции
- [ ] Все topic-файлы приведены к единому формату
```

**Стадия "Исполнение":**
```markdown
## ПЛАН ВНЕДРЕНИЯ

**Статус:** в работе

**Критерии завершённости:**
- [ ] Спецификация добавлена в базовые инструкции
- [x] Все topic-файлы приведены к единому формату

### Шаг 1: ...
**Статус:** DONE

### Шаг 2: ...
**Статус:** WIP
```

#### Роль секретаря

При выполнении `/secretary`:
1. Оценить текущую стадию темы
2. Сформулировать своё понимание критериев завершённости
3. Человек корректирует

### Правила по секциям

#### МОТИВАЦИЯ

- Зачем этот документ, какую проблему решаем
- Первая содержательная секция после заголовка
- Без мотивации документ — сирота

#### ССЫЛКИ

- Ссылки на другие файлы проекта
- Формат: `- [название](путь) — краткое описание`

#### НАРРАТИВ

- История развития мысли
- Ключевые повороты и решения
- Цитаты из чата `> [ALA] ...`
- Любые тематические подсекции (H3) — здесь

#### ВЫХОДЫ

- Структурированный результат работы над темой
- Фокус на продукте, не на процессе
- Структура внутри (H3, H4) — кастомная под тему

#### ПЛАН ВНЕДРЕНИЯ

- Критерии завершённости (Definition of Done)
- Шаги с state machine (см. topic_context_persistence.md)
- Всегда последняя секция в документе

### Типы файлов в чат-папке

| Файл | Описание |
|------|----------|
| `index.md` | Индекс чат-папки |
| `instructions.md` | Инструкции для сессии |
| `draft_*` | Личный блокнот, AI не трогает |
| `topic_*` | Обсуждение тем/проектов/идей |
| `role_*` | Обсуждение AI-ролей |
