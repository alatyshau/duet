# Сохранение контекста задач (Context Persistence)

**Статус:** В работе

---

## МОТИВАЦИЯ

### Проблема

В IDE с AI-чатом (Cursor, Cloud Code) происходит **Compaction Context** — сжатие или обрезка истории чата для экономии токенов.

**Последствия:**
1. **Потеря постановки задачи:** Агент забывает исходную инструкцию.
2. **Галлюцинации планов:** Агент начинает "домысливать", что ему делать.
3. **Бесконечные циклы:** Агент зацикливается на выполнении плана без проверок.
4. **"Вылетание вперёд":** Агент воспринимает "хорошо" как разрешение продолжать.

### Цель

Обеспечить **Persistence (живучесть)** оперативных планов, чтобы они переживали compaction context.

### @turn(260112_014515M) — Начало сессии = DIALOGUE

Правило защиты от автозапуска:

> **WIP в файле ≠ автоматический EXECUTE**

Даже если агент видит WIP-шаг при старте сессии, он:
1. Начинает в режиме DIALOGUE
2. Сообщает: "с прошлой сессии остался WIP-шаг, продолжить?"
3. Переходит в EXECUTE только после явного "да"

**Почему:** Новая сессия = потеря контекста чата. Автоматическое продолжение опасно — агент может не понимать текущую ситуацию.

## ВЫХОДЫ

### State machine шагов

```
TODO ──/next──► WIP ──(агент)──► IN_REVIEW ──/done──► DONE
                                    │
                                    └──(правки по замечаниям)──┘
```

| Статус | Владелец | Агент может |
|--------|----------|-------------|
| `TODO` | User | ❌ Ждать `/next` |
| `WIP` | Agent | ✅ Работать |
| `IN_REVIEW` | User | ⚠️ Только по запросу user |
| `DONE` | — | ❌ Закрыто |

### Команды (explicit triggers)

| Команда | Действие | Переход |
|---------|----------|---------|
| `/next` | Начать следующий шаг | TODO → WIP |
| `/done` | Закрыть текущий шаг | IN_REVIEW → DONE |
| `/done-next` | Закрыть И начать следующий | IN_REVIEW → DONE + TODO → WIP |

**Ключевое правило:**
> `/done` ≠ `/next`. Закрытие шага НЕ даёт разрешения начать следующий.
>
> Междометия ("хорошо", "ок", "круто") — это feedback, НЕ команда.

### Формат шага

Каждый шаг — заголовок H3:

```markdown
### Шаг 1: Добавить валидацию
**Статус:** TODO

**Ход работы:**
- [ ] Создать JSON Schema
- [ ] Подключить AJV
```

**"Ход работы"** — универсальное название:
- До начала: план что делать (чеклист или параграф)
- После: лог что сделано

### Типичное состояние плана

```
### Шаг 1 — DONE
### Шаг 2 — IN_REVIEW
### Шаг 3 — IN_REVIEW
### Шаг 4 — WIP ← агент здесь (обычно один)
### Шаг 5 — TODO
```
